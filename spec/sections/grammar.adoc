== Grammar

The following is the formal grammar in EBNF notation. Terminals are
quoted; productions `::=` use `|` for alternatives, `[ ]` for
optional groups, `{ }` for zero-or-more, and `< >` for non-terminal
names. Comments after `#` are not part of the grammar.

=== Top-level

[source,ebnf]
----
file            ::= { top-level } ;

top-level       ::= meta-block
                  | system-block
                  | faults-block
                  | times-block
                  | currents-block
                  | scenario-block
                  | relay-block
                  | device-block
                  | grade-block
                  | annotate-block
                  | point-block
                  | combine-block
                  | group-block
                  | view-block
                  | page-block
                  | notes-block ;
----

=== Meta

[source,ebnf]
----
meta-block      ::= "meta" "{" { meta-stmt } "}" ;
meta-stmt       ::= identifier "=" value ";" ;
                    (* open-ended; see the conventional keys below *)
----

=== System

[source,ebnf]
----
system-block    ::= "system" "{" { system-assignment } "}" ;
(* `frequency_Hz` and `grounding` were removed before 0.1.0: both were
   parsed, stored and read by nothing, and `zero_sequence` declares
   what `grounding` was reaching for. *)
system-assignment ::=
      "base_S"         "=" number power-unit ";"
    | "I_base"         "=" number current-unit ";"
    | "I_units"        "=" pickup-units-keyword ";"
    | voltages-block
    | transformer-block
    | zero-sequence-block
    | comment-asg ;

(* What is between two levels, off the nameplate. The turns ratio refers
   a *balanced* current correctly and nothing else: a delta-star
   transition recombines the sequence components differently on the far
   side, so a phase-phase fault on the star side stands 2/sqrt(3)
   further out than the ratio gives. The group also settles
   zero-sequence continuity, which `zero_sequence` may still override
   for a case the windings alone do not decide. *)
transformer-block ::= "transformer" voltage-ref "to" voltage-ref
                      "{" "vector_group" "=" string ";" "}" ;

voltages-block  ::= "voltages" "{" { voltage-asg } "}" ;
voltage-asg     ::= string "{" { voltage-member } "}" ;
voltage-member  ::= "V"          "=" number voltage-unit ";"
                  | "description" "=" string ";"
                  | comment-asg ;
voltage-ref     ::= string ;
----

The `string` in `voltage-asg` is the *name* of the voltage level;
all `voltage-ref`s elsewhere in the source refer to it by the
same string. No `level` keyword is needed; quoting is optional
when the name is a bare identifier.

=== Faults (named fault currents, each at a voltage level)

The `faults` block declares a flat, named table of fault currents.
Each fault is *at a specific voltage level* (declared via
`voltage = "<name>"`) so the *figure-of-merit* of the fault is a
primary-ampere value at that level.

[source,ebnf]
----
faults-block    ::= "faults" "{" { fault-asg } "}" ;
fault-asg       ::= string "{" { fault-member } "}" ;
fault-member    ::= "type"    "=" fault-type-keyword ";"
                  | "I"        "=" number current-unit ";"
                  | "I_min"      "=" number current-unit ";"
                  | "I_max"      "=" number current-unit ";"
                  | "I1"       "=" number current-unit ";"
                  | "I2"       "=" number current-unit ";"
                  | "I0"       "=" number current-unit ";"
                  | "residual"    "=" number current-unit ";"
                  | "voltage"    "=" voltage-ref
                  | "description" "=" string ";"
                  | comment-asg ;
----

There is no `bus` wrapper. A fault is a property of the system,
not a physical bus -- the user's relay connects to it by name
through `relay { faults = ["F1", "F2"]; }`, and a `grade` block
references it as `fault = "F1";`. The processor uses the
voltage-level name on the fault to compute cross-voltage grading
margins automatically.

=== Times (named required clearances)

The horizontal counterpart of `faults`: a limit the curves are judged
against rather than a current they are evaluated at. A time carries no
voltage level, a second being a second at every level.

[source,ebnf]
----
times-block     ::= "times" "{" { time-asg } "}" ;
time-asg        ::= string "{" { time-member } "}" ;
time-member     ::= "t"         "=" number time-unit ";"
                  | time-anchor-asg
                  | "type"      "=" fault-type-keyword ";"
                  | scoped-view-asg
                  | "description" "=" string ";"
                  | comment-asg ;

(* Where along the rule to write its caption. A rule spans the whole
   plot, so the name has no natural anchor and goes at the left-hand
   end without one. `at_I` alone is a *phase* current; on an abscissa
   in another quantity the component is named, on the same vocabulary
   a `fault`, a `point` and an `annotate` use. *)
(* "at_3I0" is an alias for "at_residual" -- the same figure, spelled
   the way `quantity` itself names the residual component. *)
time-anchor-asg ::= ( "at_I" | "at_I1" | "at_I2" | "at_I0"
                    | "at_residual" | "at_3I0" )
                    "=" number current-unit ";" ;

(* Which sheets a mark belongs to, by `view` name. Absent means every
   sheet. Accepted on `faults`, `times`, `currents`, `point` and
   `annotate`: a study with a phase sheet and a sequence sheet
   routinely carries marks that mean something on one and nothing on
   the other.

   `~name` reads "every declared one except this" instead of naming
   one. A list is read as an include list or an exclude list, decided
   by its first entry; mixing the two (`[A, ~B]`) is refused, since
   there is no single reading of it. The same `~` works in a
   `condition-list` (see "Faults" / "Named conditions" above). *)
scoped-view-asg ::= ( "view" | "views" ) "=" name-or-list ";" ;
name-or-list    ::= list-name | "[" [ list-name { "," list-name } [ "," ] ] "]" ;
list-name       ::= [ "~" ] string ;
----

=== Currents (named plant/equipment ratings)

`times`'s counterpart in the other direction: a rating drawn as a
vertical rule rather than a condition curves are evaluated at. It
carries the same component vocabulary a `fault` does, and no voltage
level -- there is nothing to refer a nameplate figure *from*. Never
usable where a `grade` or `scenario` takes a condition.

[source,ebnf]
----
currents-block  ::= "currents" "{" { current-asg } "}" ;
current-asg     ::= string "{" { current-member } "}" ;
current-member  ::= "I"          "=" number current-unit ";"
                  | "I1"         "=" number current-unit ";"
                  | "I2"         "=" number current-unit ";"
                  | "I0"         "=" number current-unit ";"
                  | "residual"   "=" number current-unit ";"
                  | "at_t"       "=" number time-unit ";"
                  | "type"       "=" fault-type-keyword ";"
                  | scoped-view-asg
                  | "name"       "=" string ";"
                  | "description" "=" string ";"
                  | comment-asg ;
----

=== Relay

[source,ebnf]
----
name-asg        ::= "name" "=" string ";" ;

scenario-block  ::= "scenario" string "{" { scenario-member } "}" ;
scenario-member ::= "description" "=" string ";"
                  | comment-asg
                  | scenario-level
                  | scenario-share ;
scenario-level  ::= "level" string "{" { level-member } "}" ;
zero-sequence-block ::= "{" { zero-sequence-link } "}" ;
zero-sequence-link  ::= string "to" string "=" ( "blocked" | "continuous" ) ";" ;

scenario-type   ::= "type" "=" fault-type-keyword ";" ;
fault-type-keyword ::= "three_phase" | "two_phase"
                  | "two_phase_earth" | "single_phase_earth" ;

axis-quantity   ::= "any"        # every curve on one current axis (default)
                  | measured-quantity ;
measured-quantity ::= "phase" | "I1" | "I2" | "3I2" | "I0" | "3I0" ;

level-member    ::= "I"     "=" number current-unit ";"   # phase
                  | "I1"    "=" number current-unit ";"
                  | "I2"    "=" number current-unit ";"
                  | "I0"    "=" number current-unit ";"   # component
                  | "residual" "=" number current-unit ";" ; # residual 3*I0
scenario-share  ::= "sees" identifier "{" "share" "=" number ";" "}" ;

relay-block     ::= "relay" identifier "{" { relay-member } "}" ;
relay-member   ::= relay-scalar ";"
                  | element-block ;
relay-scalar   ::= "name"       "=" string   # display name; id stays the reference
                  | "maker"      "=" string
                  | "model"      "=" string
                  | "voltage"    "=" voltage-ref
                  | "ct_ratio"   "=" ratio
                  | "faults"     "=" "[" fault-ref-list "]" ";"
                  | "comment"    "=" string ";"
                  | "description" "=" string ";"
                  | "reference"  "=" string ";"
                  ;
ratio           ::= number "/" number ;
voltage-ref     ::= string ;
fault-ref-list  ::= fault-ref { "," fault-ref } ;
fault-ref       ::= fault-id ;
fault-id        ::= string ;
----

A `relay` block declares its voltage level by reference (using
`voltage = "LV"` and similar). The relay does not carry the
numerical voltage directly; the numeric value lives in the
`system.voltages` block. The relay may also list the `faults` that
it considers itself bounded-by (the engineer's fault list); a
`grade` block may then reference any of those fault ids directly.

=== Element

The element block is the central entity in the language. An element
block either:

* declares its characteristic inline (one of `curve`, `formula`,
  `flex_points`, or `curve=definite` plus optional pickup /
  tms / t_delay / ... -- shorthand for a single implicit *stage*
  named `main`), or
* declares a `stages` sub-block containing one or more named
  `stage <id> { ... }` sub-blocks.

Both forms are equivalent in that at least one curve producer must be
present; an element with `stages` cannot additionally carry inline
producer fields -- the shorthand and explicit forms are mutually
exclusive (validated in <<validation,Validation>>).

The rendered TCC draws a *single curve per element* as the pointwise
minimum across all of its stages (the operative-time envelope). The
toggle `view.stages = "composite" | "individual"` switches between
the composite and the per-stage individual visible curves. See
<<semantics,Semantics>> for the default and rationale.

[source,ebnf]
----
element-block   ::= "element" element-id "{" { element-member } "}" ;
element-member  ::= name-asg
                  | function-asg
                  | measures-asg
                  | curve-asg
                  | formula-asg
                  | flex_points-asg
                  | pickup-asg
                  | pickup_units-asg
                  | current_pct-asg
                  | tms-asg
                  | t_delay-asg
                  | I_cutoff-asg
                  | curve-drawing-asg
                  | scoped-view-asg
                  | comment-asg
                  | stages-block ;

(* Where this characteristic stops. An element or a stage says it;
   a `view` says `current_max`, which is an axis bound and a different
   thing. *)
I_cutoff-asg ::= "I_cutoff" "=" number current-unit ";" ;

(* How one characteristic is stroked, overriding the sheet's palette
   and line weight. Accepted on an `element` and on a `stage`; a stage
   that declares none inherits its element's. *)
curve-drawing-asg ::= "color"    "=" string ";"
                    | "style"    "=" curve-style-keyword ";"
                    | "width_px" "=" number ";" ;
curve-style-keyword ::= "solid" | "dashed" | "dotted" ;

comment-asg     ::= "comment" "=" string ";" ;
element-id      ::= number | identifier ;

function-asg    ::= "function"    "=" function-keyword ";" ;
function-keyword ::= "phase_oc" | "earth_fault" | "neg_seq"
                   | "thermal" | "breaker_fail" ;

(* Which current the pickup is expressed in. Defaulted from `function`
   where the standards make it unambiguous; required for `neg_seq`,
   where IEDs differ over the factor of three. *)
measures-asg    ::= "measures"    "=" measured-quantity ";" ;

curve-asg       ::= "curve" "=" ( curve-id | "definite" ) ";" ;
curve-id        ::= identifier "." identifier ;

[NOTE]
====
The grammar *only* requires `curve` to be the shape
`identifier "." identifier`. The parser does *not* validate
`"iec"`, `"ansi"`, etc.; the namespace list is a validator
constant (in `src/constants/curves.ts`), not a parser-level
clause. As a result, a new vendor can be added in a single
loc without grammar rewrites -- and the parser does not need
to be re-tested for the new namespace. See
<<validation,Validation>> for the closure rule.
====

formula-asg     ::= "formula" "=" "{" { formula-member } "}" ";" ;
formula-member  ::= "k"     "=" number time-unit ";"
                  | "c"     "=" number time-unit ";"
                  | "alpha" "=" number ";" ;

flex_points-asg ::= "flex_points" "=" "[" flex-pt { "," flex-pt } "]" ";" ;
flex-pt         ::= "(" number current-unit "," number time-unit ")" ;

pickup-asg      ::= "I_pickup" "=" number current-unit ";" ;
pickup_units-asg ::= "I_units" "=" pickup-units-keyword ";" ;
pickup-units-keyword ::= "primary" | "secondary" ;
current_pct-asg ::= "share" "="
                  number "%" ";" ;
tms-asg         ::= "tms"       "=" number ";" ;
t_delay-asg     ::= "t_delay"   "=" number time-unit ";" ;

stages-block    ::= "stages" "{" { stage-block } "}" ;
stage-block     ::= "stage" stage-id "{" { stage-member } "}" ;
stage-id        ::= identifier | number ;
stage-member    ::= curve-asg
                  | formula-asg
                  | flex_points-asg
                  | pickup-asg
                  | pickup_units-asg
                  | current_pct-asg
                  | tms-asg
                  | t_delay-asg
                  | I_cutoff-asg
                  | curve-drawing-asg
                  | comment-asg ;
----

=== Grade

[source,ebnf]
----
grade-block     ::= "grade" "{" { grade-member } "}" ;
grade-member    ::= "primary"   "=" ref ";"
                  | "backup"    "=" ref ";"
                  | "fault"     "=" fault-ref ";"
                  | "margin" "=" number time-unit ";"
                  | "margin_target" "=" number time-unit ";"
                  | "tolerance_pct" "=" number ";"
                  | "comment"   "=" string ";"
                  | solve-block ;

solve-block     ::= "solve" "{" { solve-member } "}" ;
solve-member    ::= "strategy" "=" solve-strategy-keyword ";"
                  | "tolerance_pct" "=" number ";"
                  | "free" "=" "[" free-list "]" ";" ;
free-list       ::= solve-free { "," solve-free } ;
solve-free      ::= "tms" | "t_delay" | "I_pickup" ;
solve-strategy-keyword ::= "tight"  # minimum tms meeting the margin
                         | "loose"  # tms rounded up to the standard step
                         | "safety_factor" ;  # multiplied by safety factor
                                       # (v0.2; requires value)
----

The `fault` field on a `grade` block is a *named fault reference*
to an entry declared in the top-level `faults { ... }` block. There
is no `transformer` clause and no keyword shorthand like
`sc_3ph_max`: the user names faults explicitly (e.g., `F1`,
`FDR_1_max`). The processor derives the cross-voltage
transformation from the fault's `voltage` and the participating
relay's `voltage` (using `system.voltages`).

A `grade` block may carry *zero or more* of:

* `margin` -- minimum acceptable margin (a *constraint*);
* `margin_target` -- *exact* design margin at the declared fault (a
  *target*);
* `tolerance_pct` (default 0) -- allowance above `margin_target` for the
  solver.

When the `solve` block is present, the engineer has declared that the
tool should *compute* the free variables (default: `tms`) such that
the grading margin matches `margin_target` (or `margin` if `margin_target`
is omitted) at the declared `fault`. See
<<semantics,Semantics>> _Solver -- automatic grading_.

=== Annotations and marked points

[source,ebnf]
----
annotate-block  ::= "annotate" "{" { annotate-member } "}" ;
annotate-member ::= "on_curve" "=" ref ";"          (* point form *)
                  | "primary"  "=" ref ";"          (* margin form *)
                  | "backup"   "=" ref ";"
                  | "point"    "=" point-id ";"     (* curve-to-point margin *)
                  | time-anchor-asg
                  | "at_t"   "=" number time-unit ";"
                  | "type"     "=" fault-type-keyword ";"
                  | span-asg                          (* span form *)
                  | condition-asg
                  | scoped-view-asg
                  | "label"    "=" string  ";"
                  | "style"    "=" annotation-style ";"
                  | "color"    "=" color-value ";"
                  | "coords"   "=" boolean ";"
                  | comment-asg ;
annotation-style ::= "leader" | "pin" | "tag" ;

(* A dimension between two figures the study names, with no curve at
   either end. The *unit* selects the orientation: two times draw a
   vertical span, two currents a horizontal one. Both ends must be of
   the same quantity. A currents end may instead name a declared fault
   or scenario -- "from 840 A to F_HV_3PH" -- resolved to that
   condition's own current; there is no such thing as a named time. *)
span-asg        ::= ( "from" | "to" ) "=" span-end ";" ;
span-end        ::= number ( current-unit | time-unit ) | condition-name ;

point-block     ::= "point" point-id "{" { point-member } "}" ;
point-id        ::= string | identifier ;
(* A point declares its current exactly as a `fault` does, so one
   vocabulary covers every current in the language; the sheet takes
   whichever component its axis is drawn in. *)
point-member    ::= "I"     "=" number current-unit ";"   # phase
                  | "I1"    "=" number current-unit ";"
                  | "I2"    "=" number current-unit ";"
                  | "I0"    "=" number current-unit ";"   # component
                  | "residual" "=" number current-unit ";"   # residual 3*I0
                  | "type"    "=" fault-type-keyword ";"
                  | "t"     "=" number time-unit ";"
                  | condition-asg
                  | "voltage" "=" voltage-ref ";"
                  | "label"   "=" string ";"
                  | "shape"   "=" point-shape ";"
                  | "color"   "=" color-value ";"
                  | "coords"  "=" boolean ";"
                  | "description" "=" string ";"
                  | comment-asg ;
point-shape     ::= "circle" | "square" | "diamond" | "triangle"
                  | "cross" | "x" ;
----

A **condition reference** names one or more declared conditions -- a
`fault` or a `scenario`, which are alternative ways of naming the same
thing. All four spellings of the key are equivalent, and each accepts a
single name or a list:

[source,ebnf]
----
condition-asg   ::= condition-key "=" condition-list ";" ;
condition-key   ::= "fault" | "faults" | "scenario" | "scenarios" ;
condition-list  ::= condition-name
                  | "[" condition-name { "," condition-name } "]" ;
(* The `.level` suffix names one of a scenario's own declared levels
   directly, overriding whatever level a marker's `voltage` or the
   element it is on would otherwise supply. Meaningless for a `fault`,
   which has only the one level it was declared at.

   A leading `~` reads "every declared fault and scenario except this
   one", the same as in a `views` list; a list mixing `~` with a plain
   name is refused for the same reason. *)
condition-name  ::= [ "~" ] ( string | identifier ) [ "." ( string | identifier ) ] ;
----

A block naming several conditions is drawn once per condition, each at
that condition's own current. Repeated names are drawn once. See
<<semantics,Semantics>> _Conditions on the drawing_.

notes-block     ::= "notes" "{" { identifier "=" value ";" } "}" ;

=== Device -- auxiliary TCC assets

The `device` block declares an *auxiliary TCC asset*: a fuse, a
cable-withstand curve, a transformer-damage curve, a recloser
control curve, a motor-startup curve, or a breaker clearing-time
curve. Devices may be referenced by name from `grade { primary ...;
backup ...; }` and `combine { sources = [...]; }` blocks.

A device TCC is **always piecewise** (the `flex_points` field is
required); the standard inverse-time formulas are relay-element
curves and not used for devices.

[source,ebnf]
----
device-block    ::= "device" device-id "{" { device-member } "}" ;
device-id       ::= string | identifier ;
device-member   ::= "kind"      "=" device-kind-keyword ";"
                  | "voltage"   "=" voltage-ref ";"
                  | "maker"     "=" string ";"
                  | "model"     "=" string ";"
                  | "rating_I"  "=" number current-unit ";"
                  | "rating_V" "=" number voltage-unit ";"
                  | "rating_S" "=" number power-unit ";"
                  | "comment"   "=" string ";"
                  | "description" "=" string ";"
                  | "reference" "=" string ";"
                  | flex_points-asg
                  | "min_melt"  "=" "[" flex-pt { "," flex-pt } "]" ";"
                  | "total_clear" "=" "[" flex-pt { "," flex-pt } "]" ";"
                  | "t_delay"   "=" number time-unit ";" ;

device-kind-keyword ::= "fuse" | "recloser" | "cable"
                      | "transformer_damage" | "motor_startup"
                      | "breaker" ;
----

A `device` block with `kind = "fuse"` may carry *either* a single
`flex_points` table (single-curve fuse) *or* both `min_melt` and
`total_clear` tables (fuse band). The renderer shades the band
between `min_melt` and `total_clear` automatically; no `combine`
block is needed.

A `breaker` device may carry only `t_delay` (no `flex_points`);
the resulting curve is a single horizontal line.

==== No built-in catalogue

A device carries its own table. There is no shipped catalogue of
vendor curves and no shorthand that expands into one.

Earlier drafts published a table of eight shorthands
(`ferraz_abc_100a`, `tx_25mva_11kv` and so on) as *"real data sourced
from the manufacturer's published TCC bulletin"*. Nothing ever read
it: the lookup had no callers, so those shorthands resolved as
ordinary device ids and produced `DEVICE_NO_CURVE`. It is withdrawn
rather than implemented, for two reasons.

A curve is a number a study depends on, and one taken from a table
inside the tool is a number the reader cannot trace. The `reference`
field exists so that a device says where its data came from --
"Mersen T-link data sheet, table 2" -- which is the practice a
coordination study is reviewed against. A built-in table replaces
that with the processor's word for it.

The second is simpler: redistributing manufacturers' published curves
is theirs to permit, and eight approximate five-point tables are not
worth the question.

==== Reference syntax

A device is referenced by its `device-id` *without* a colon, as
distinct from a `relay:element` reference which always has a colon:

[source,tc]
----
grade {
    primary   = fuse_load:abc_min_melt;     // NOT a device-ref (see below)
    backup    = R_TRF_INC:51;
    fault     = "F_load_max";                // named fault reference
    margin_target = 0.15 s;
}
----

Carefully: the suffix `fuse_load:abc_min_melt` does *not* resolve as
a device reference (it has a colon). The correct reference for a
device is the *plain* `device-id`:

[source,tc]
----
grade {
    primary   = ferraz_abc_100a;            // device-ref (no colon)
    backup    = R_TRF_INC:51;               // relay-ref (with colon)
    fault     = "F_load_max";               // named fault reference
    margin_target = 0.15 s;
}
----

The same `primary` / `backup` fields accept either form, decided by
the *presence of `:`*.

=== Combine -- synthetic curves

`combine` declares a *synthetic curve* drawn from one or more existing
curves on the TCC. The processor produces a derived curve from the
declared sources; it never modifies the source curves themselves.

`combine` is analogous to a `view` directive and is *not* a grading
construct: `grade { ... }` blocks still operate on real elements
only.

[source,ebnf]
----
combine-block   ::= "combine" "{" { combine-member } "}" ;
combine-member  ::= "name"        "=" identifier ";"
                  | "sources"     "=" "[" source-list "]" ";"
                  | "as"          "=" combine-as-keyword ";"
                  | "voltage"     "=" identifier ";"
                  | "color"       "=" string ";"
                  | "style"       "=" combine-style-keyword ";"
                  | "label"       "=" string ";"
                  | comment-asg ;
source-list     ::= ref { "," ref } ;
combine-as-keyword ::=
      "envelope_min"       # pointwise min(t1, t2, ...)  -- "OR" of trips
    | "envelope_max"       # pointwise max(t1, t2, ...)  -- "AND" of trips
    | "sum"                # pointwise t1 + t2 + ...
    | "select_first" ;     # adopt t of the first source only
combine-style-keyword ::= "solid" | "dashed" | "dotted" ;

# A 'source' in a `combine` block, or 'primary'/'backup' in a `grade`
# block, may be either a relay-ref (with colon) or a device-ref
# (plain identifier). The grammar disambiguates by the colon.
ref ::= relay-ref | device-ref ;
relay-ref   ::= identifier ":" ( element-id | identifier ) ;
device-ref  ::= identifier ;
----

=== Group (a protection chain)

A protection chain: the relays in series on one path, upstream first.
A `view` selects by `group`, so a sheet draws exactly that chain
instead of every element listing every sheet it belongs on.

[source,ebnf]
----
group-block     ::= "group" identifier "{" { group-member } "}" ;
group-member    ::= "members"     "=" "[" identifier { "," identifier } "]" ";"
                  | "name"        "=" string ";"
                  | "description" "=" string ";"
                  | comment-asg ;
----

=== View (display directives)

[source,ebnf]
----
(* A study may declare several views; each is one sheet. The optional
   name identifies it to a reader and to a sheet picker. *)
view-block      ::= "view" [ string ] "{" { view-member } "}" ;
view-member     ::= "name"          "=" string ";"
                  | "default"       "=" boolean ";"
                  | "group"         "=" identifier ";"
                  | "stages"        "=" view-stages-keyword ";"
                  | "axis"          "=" view-axis-keyword ";"
                  | "quantity"      "=" axis-quantity ";"
                  | "condition"     "=" condition-name ";"
                  | "voltage"       "=" voltage-ref ";"
                  | "title"         "=" string ";"
                  | "subtitle"      "=" string ";"
                  | "current_min"   "=" number current-unit ";"
                  | "current_max"   "=" number current-unit ";"
                  | "time_min"      "=" number time-unit ";"
                  | "time_max"      "=" number time-unit ";"
                  | "second_axis"   "=" identifier ";"
                  | "reference_ct"  "=" ref ";"

=== Page (page / theme / legend / colours)

The `page` block declares layout, decoration, legend, and colour
options for the rendered output. SVG, PNG, and PDF outputs *all*
consume these settings; for PNG/PDF the page size and orientation
map directly to canvas / PDF dimensions, while SVG honours the
viewBox (with margins baked into the document).

[source,ebnf]
----
page-block      ::= "page" "{" { page-member } "}" ;
page-member     ::= "size"           "=" size-value ";"
                  | "orientation"    "=" orientation-keyword ";"
                  | "margins_mm"     "=" margins-block ";"
                  | "margins_mm"     "=" number ";"   # all four sides
                  | "scale"          "=" scale-block ";"
                  | "legend"         "=" legend-block ";"
                  | "axes"           "=" axes-block ";"
                  | "curves"         "=" curves-block ";"
                  | "points"         "=" points-block ";"
                  | "leaders"        "=" leaders-block ";"
                  | "title"          "=" title-block ";"
                  | "footer"         "=" footer-block ";"
                  | "theme"          "=" theme-keyword ";"
                  | "watermark"      "=" string ";"
                  | "stretch"        "=" boolean ";" ;

size-value      ::= paper-keyword | "{" "width_mm" "=" number ";"
                                            "height_mm" "=" number ";" "}" ;
paper-keyword   ::= "A4" | "A3" | "A5" | "Letter" | "Legal"
                  | "Tabloid" | "A0" | "A1" | "A2" ;
orientation-keyword ::= "portrait" | "landscape" ;

margins-block   ::= "{" { margin-member } "}" ;
margin-member   ::= "top"    "=" number "mm" ";"
                  | "right"  "=" number "mm" ";"
                  | "bottom" "=" number "mm" ";"
                  | "left"   "=" number "mm" ";" ;

scale-block     ::= "{" { scale-member } "}" ;
scale-member    ::= "auto"   "=" boolean ";"
                  | "x_min"  "=" number current-unit ";"
                  | "x_max"  "=" number current-unit ";"
                  | "y_min"  "=" number time-unit ";"
                  | "y_max"  "=" number time-unit ";"
                  | "tick_density" "=" tick-density-keyword ";" ;
tick-density-keyword ::= "sparse" | "normal" | "dense" ;

legend-block    ::= "{" { legend-member } "}" ;
legend-member   ::= "show"      "=" boolean ";"
                  | "style"     "=" legend-style ";"
                  | "position"  "=" legend-position ";"
                  | "color"     "=" color-value ";"
                  | "swatch"    "=" legend-swatch-keyword ";"
                  | "currents"  "=" legend-currents ";"
                  | "notes"     "=" boolean ";"
                  | "comment"   "=" text-lines ";"
                  | "title"     "=" string ";" ;

   block the tool writes about what it could not draw. One string, or a
   list of lines; a `\n` inside a single string breaks it the same way,
   and blank lines are dropped rather than drawn as gaps. *)
text-lines      ::= string | "[" [ string { "," string } [ "," ] ] "]" ;
(* Which amps the legend quotes a pickup in. Independent of
   `view { axis }`, which decides the abscissa; `secondary` and `both`
   need the relay's `ct_ratio` and fall back to primary without one. *)
legend-currents ::= "primary"    # as declared (default)
                  | "secondary"  # divided by ct_ratio
                  | "both" ;     # primary, with the secondary in brackets
legend-style    ::= "column"    # default; a gutter down the right
                  | "inside"    # the same panel, floated on the plot
                  | "direct"    # no panel; each curve labelled in place
                  | "none" ;    # no identification at all

                  | "top_right" | "top_left"
                  | "bottom_right" | "bottom_left" ;

                  | "grid_color" "=" color-value ";"
                  (* The minor lines separately. A log axis draws nine
                     per decade and only one is a labelled power of ten;
                     told apart by weight alone the reader has to count.
                     Unset, they take the major colour. *)
                  | "grid_minor_color" "=" color-value ";"
                  | "grid_style"       "=" grid-style ";"
                  | "grid_minor_style" "=" grid-style ";"
                  | "label_color" "=" color-value ";"
                  | "label_size_px" "=" number ";"
                  | "tick_size_px"   "=" number ";"
                  | "frame"          "=" boolean ";" ;

grid-style      ::= "solid" | "dashed" | "dotted" ;

curves-block    ::= "{" { curves-member } "}" ;
curves-member   ::= "palette"     "=" palette-value ";"
                  | "line_width_px" "=" number ";"
                  | "auto_color"   "=" boolean ";" ;

==== Theme presets

The `theme` keyword sets a coordinated bundle of colours:

[cols="1,1,1,3", options="header"]
|===
| `theme` | background | axis colour | use case

| `light`      | white    | dark gray  | default; playground & on-screen
| `dark`       | #1e1e1e  | light gray | dark-mode playground
| `monochrome` | white    | black      | black-and-white print, archival
| `print`      | white    | black      | ICC-aware print (full CMYK separation, ICC profile in PDF)
|===

==== Names

`relay` and `element` may each carry a `name`: free text, shown
wherever the drawing identifies that characteristic -- the legend, a
direct label, the hover readout.

[source,tc]
----
relay R_INC {
    name = "Incomer 11 kV, panel 3";
    element 51 { name = "Phase OC (main)"; curve = iec.si; I_pickup = 600 A; tms = 0.3; }
}
----

The `id` remains the reference. `grade`, `annotate`, and `combine`
resolve `R_INC:51` exactly as before, so renaming something for the
reader can never break a reference to it. Where both are named the
parts are joined with a middot (`Incomer 11 kV, panel 3 · Phase OC
(main)`) rather than a colon, which would read as though it were
structural. A study that declares no names is unchanged: the label is
the reference.

==== Filling the sheet

The drawing is sized to the *printable* area -- the paper less
`margins_mm` -- so a portrait study fills its page rather than being
letterboxed into it. `margins_mm = 0;` is shorthand for all four
sides, and makes the sheet edge to edge.

Within that sheet the plot rectangle still gives up a fixed band below
the axis, sized for the worst case: several fault names stacked into
rows. `page { stretch = true; }` measures that band instead of
reserving for it, handing the difference to the plot. The reserve
never drops below what the names actually need, so a study whose
faults stack onto four rows keeps its room.

`stretch` affects the vertical only. Width is governed by
`legend.style` (below) and by `margins_mm`.

==== Legend placement

`legend.style` decides how the curves are identified, and therefore
how much of the sheet the plot itself gets.

[cols="1,3", options="header"]
|===
| Style | Behaviour

| `column`
| Default. A gutter down the right-hand side carrying the *Curves*,
  *Points*, and *Faults* sections. Costs roughly 330 px of width.

| `inside`
| The same panel, floated over a corner of the plot on an opaque card
  and pinned by `legend.position` (`top_right` by default). The gutter
  is released to the plot.

| `direct`
| No panel. Each characteristic is labelled where it runs, in a boxed
  label with a leader back to the curve. Points and faults keep the
  labels they already carry on the plot.

| `none`
| No identification at all. Equivalent to the older `show = false`.
|===

An explicit `style` wins over `show`, so `show = false; style =
"direct";` labels the curves directly rather than suppressing them.

[NOTE]
====
On a *portrait* sheet the gutter is the difference between a readable
decade span and a cramped one, so `inside` and `direct` are the
placements to reach for there. `direct` is also the stronger reading
on any crowded sheet: the eye never has to leave the curve to match a
colour against a key. Labels are anchored at the right-hand end of
each characteristic -- where TCC curves are flattest and furthest
apart -- and then spread vertically so that none overlap, each keeping
a leader to its true anchor.
====

==== A crowded sheet

A legend is laid out at the fullest detail that fits the space it
has, and only then starts dropping entries:

. *full* -- every entry with its make, model, and settings, and each
  fault with its `description`;
. *compact* -- the settings line only, which is the line an engineer
  checks, with the make and model and the fault notes dropped;
. *minimal* -- names alone;
. finally, entries are dropped and the count is printed as
  `+N more not shown`.

The choice is made by laying the legend out and measuring it, since
the wrapping depends on the text. A study with a couple of relays is
unaffected; one with nine characteristics and seven described faults
degrades rather than running off the bottom of the page and over the
title block.

`legend { style = "direct" }` is the other answer to a crowded sheet:
it removes the panel entirely and labels each characteristic where it
runs. On a study with many curves at similar times, though, the column
is easier to read than a stack of boxed labels.

==== Precedence

When more than one field affects the same rendering (e.g. a
per-curve colour override vs the `curves.palette` setting), the
*narrower* scope wins:

. *Hard-coded render defaults* (lowest).
. *Page-block declarations* (here).
. *Per-element / per-stage colour overrides* (medium; rare).
. *CLI / playground overrides* (highest; not persisted to source).

A `theme = "dark"` declaration automatically sets `axes.color =
#eee`, `axes.grid_color = #333`, `legend.color = #eee`,
`points.color = #eee`, etc. Page-block fields may override
specific `theme` choices without re-specifying the whole theme.
