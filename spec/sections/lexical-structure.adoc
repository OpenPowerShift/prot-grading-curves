== Lexical structure

* Encoding: UTF-8. ASCII is sufficient; future extensions may add
  Greek / subscript glyphs.
* Line endings: LF (recommended) or CRLF (tolerated).
* One top-level block per line, terminated by `;` where applicable, or
  delimited by `{ ... }`.

=== Whitespace

* Spaces and tabs are interchangeable tokens between identifiers and
  operators.
* Newlines separate statements *inside* a block. Block terminators
  (`}`, `;`) do not require a following newline.
* Blank lines, line comments, and block comments are tolerated anywhere
  a newline is expected.

=== Comments

* `# ...` (to end of line) -- recommended for engineer notes.
* `// ...` (to end of line) -- accepted for parity with C / JavaScript.
* `/* ... */` -- block comments; do *not* nest.

=== Identifiers

There are three kinds, with different rules.

*Curve identifiers* -- lowercase letters, digits, underscores, and
periods. Must not start with a digit. The period (`.`) is the
*namespace separator* (`iec.si`, `ge.ur.vi`); the namespace is the
text before the *first* period, so a family may itself contain one.
Namespaces are lowercase and processor-known: `iec`, `ansi`, `sel`,
`ge`, `abb`, `schneider`, `siemens`.

*Relay identifiers* -- uppercase and lowercase letters, digits, and
underscores; must start with a letter or underscore: `R_TRF_INC`,
`R_FDR_1`.

*Element and stage identifiers* -- IEEE C37.2 *device numbers*, so
they *may* start with a digit and may carry a letter suffix:
`50`, `51`, `67N`, `51X`, `51F`, `87T`. Formally: one or more
digits, optionally followed by letters, digits, and underscores; or
a relay-style identifier (`main`, `inst`) for a `stage`.

[NOTE]
====
Element ids are the one place a leading digit is allowed, because
the device number *is* the industry's name for the function --
writing `element 51` rather than `element E51` keeps the source
readable to a protection engineer. Since a device number is a single
token, `67N` must not be read as the number `67` followed by the
identifier `N`; a digit-leading identifier absorbs any letters that
follow it immediately, with no intervening whitespace.

The whitespace rule is what keeps `I_pickup = 480 A` unambiguous: the
space separates the value from its unit, so `480 A` is a number and
a suffix, while `67N` is one identifier.
====

=== Escapes in strings

`\"`, `\\`, `\n`, `\t` and `\u{XXXX}` are recognised.

`\n` is significant beyond the lexer: in any string the renderer
draws -- a `label`, a `times` name, a `title`, a `subtitle`, a legend
`comment` -- it SHALL break the line on the sheet. This is the only
means of controlling where a caption wraps.

=== Numbers

* Integer or decimal. Group separator `_` is permitted anywhere inside
  digits with no semantic meaning: `18_430` is identical to `18430`.
* A unit suffix is *required* wherever the field carries a quantity.
  No field has a default unit, so a bare number in a unit-bearing
  context is a *parse error* (`UNIT_MISSING`) and never an assumption.

=== Recognised units

[cols="1,3", options="header"]
|===
| Category | Units

| Current  | `A`, `kA`, `mA`, `MA`
| Current, pickup only | `A_sec` (secondary amps; multiplied by `ct_ratio`), `A_pri` (primary, explicitly)
| Time     | `s`, `ms`, `min`, `ks`
| Voltage  | `V`, `kV`, `MV`
| Power    | `MVA`, `kVA`, `GVA`, `MW`
| Angle    | `deg`
| Ratio    | _no unit_ (e.g. `ct_ratio = 600/5`)
| Per-unit | `pu`, `xCT`, `xIn`
|===

A suffix outside this table is `UNIT_UNKNOWN`; a suffix belonging to
another quantity -- `I_pickup = 5 ms` -- is `UNIT_WRONG_QUANTITY`, a
category error a check against the union of every suffix would pass.

NOTE: An earlier revision of this section said a suffix "may be
omitted" where it was the field's default, and that the linter merely
"warns on unit omissions" -- contradicting the paragraph above it and
the implementation, which refuses. There are no default units. The
rule is the stricter one, because the omission it would have permitted
is the one that reads fifty as fifty seconds where fifty milliseconds
was meant.

=== Default units per field

[cols="1,1", options="header"]
|===
| Field            | Default unit

| `tms`            | _none_
| `t_delay`        | `s`
| `t_reset`        | `s`
| `margin`      | `s`

=== Strings

* Double-quoted only. Any UTF-8 character except `"` and `\`.
* Escape sequences: `\"`, `\\`, `\n`, `\t`, `\u{XXXXX}` for arbitrary
  code points. An unrecognised escape is preserved verbatim
  (backslash included) rather than dropped.

[NOTE]
====
`\n` is meaningful in any *author-facing label* -- `point.label`,
`annotate.label`, `page.title.text`, `page.title.subtitle` -- where the
renderer breaks the text into lines. A label pinned beside a marker is
centred on it, so a second line grows the block symmetrically rather
than pushing it off the thing it names; a title or legend entry, which
is laid out top-down, hangs its extra lines below the first.

Elsewhere -- identifiers, `data-` attributes in the SVG, and the
single-line readout in the playground -- a newline is folded to a
space.
====

=== Block and statement syntax

* `{` opens a block; `}` closes one.
* A statement inside a block is one of:
** `identifier = value ;` -- a scalar assignment.
** `identifier { ... }` -- a sub-block.
** `element <id> { ... }` -- a nested block of an element.
* Top-level blocks (zero or more, in any order):
  `meta { ... }`, `system { ... }`, `faults { ... }`,
  `relay <id> { ... }`, `grade { ... }`, `annotate { ... }`,
  `notes { ... }`.
* Multiple `relay`, `grade`, `annotate`, and `notes` blocks are
  permitted per file.
