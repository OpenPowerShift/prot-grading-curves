[[spec-discrepancies]]
== Spec discrepancies resolved during implementation

Six places where the spec contradicts itself or its own worked
examples. In every case the *normative worked example* was treated as
authoritative, since those are the acceptance vectors the plan names,
and the resolution is recorded in a comment at the implementation
site. These want a spec edit to close.

. *Cross-voltage backup current.* _Cross-voltage grading_ gave the
  algorithm as `I_at_backup = I_at_primary` ("same physical current"),
  while a later paragraph wrote
  `I_at_backup = I_fault * V_fault / V_backup`. The two disagree
  whenever the pair spans a transformer.
+
--
*The second form is the correct one*, and the spec has been rewritten
around it. Ampere-turns balance across a transformer, so its windings
carry currents in inverse proportion to their voltages: a 6.4 kA fault
on an 11 kV bus drives 2.13 kA through the 33 kV winding. Each relay
must be evaluated at the current *it* measures, against its own
pick-up.

This was initially resolved the *wrong* way. The spec's worked
examples had been computed from `I_at_backup = I_at_primary`, and the
rule adopted here was "the worked examples are the conformance
vectors, so follow them". That was a mistake: the examples encoded the
error rather than testing for it. Dividing an LV current by an HV
pick-up inflates the backup's multiple and understates its operate
time, so the tool reported a grading margin that does not physically
exist -- 0.940 s instead of 1.912 s for the canonical case, a
fictitious 0.666 s margin in place of the real 1.639 s.

It surfaced because the *renderer* projects correctly and the
*report* did not, so the plot and the report disagreed on the same
study. Both worked examples and the solver case have been recomputed;
`tests/unit/margins.spec.ts` now also pins report-versus-plot
agreement in both voltage frames, so the two cannot drift apart again.

*Lesson for the remaining items below*: a worked example is only a
conformance vector to the extent that it is physically right.
Where prose and example conflict, check the physics before picking a
side.
--

. *Solver rounding for `strategy = "tight"`.* _Algorithm_ says "floor
  to the nearest 0.005", but _Worked solver case_ rounds 0.28859 to
  *0.290* and requires `tms = 0.290 +/- 0.001`. Flooring would give
  0.285 and land the margin *below* the declared target, contradicting
  "minimum tms that meets the margin". Implemented as ceiling -- see
  `snapTms` in `src/semantics/solver.ts`.

. *The `G_D` ceiling.* _Curve model_ says the processor defaults
  `G_D = 20`, but the _Operate time_ table lists `iec.si` at `M = 50`
  as 1.720 s, which is the *unclamped* value; clamping at 20 gives
  2.267 s. Since per-element `G_D` is deferred to v0.2 there is
  nothing that would switch the ceiling on, so it defaults off and is
  honoured only when a caller supplies it -- see `tTripIDMT` in
  `src/semantics/curves.ts`.

. *Tolerance band vs aim point.* _Algorithm_ aims at
  `margin_s * (1 + tolerance_pct/100)`, while the sample report calls
  the worked case "within tolerance (0.0 %)" despite `tms` having been
  rounded up. Read literally, snapping `tms` would always report an
  overshoot and the tolerance feature could never pass. The band is
  therefore widened by exactly the time the rounding step added --
  see `quantisation_s` in `src/semantics/solver.ts`.

. *Element identifiers.* _Identifiers_ says engineered identifiers
  "must start with a letter or underscore", then offers `51` as an
  example, and the canonical example file uses `50`, `51`, `67N`,
  `51X`, `51F`. Element ids are IEEE C37.2 device numbers, so they may
  lead with digits and carry a letter suffix -- see
  `parseDeviceNumberId` in `src/parser/parser.ts`.

. *`curve = ansi.e` in the canonical example.* The example file's
  `67N` element references `ansi.e`, which is not a row in the
  constants table (the ANSI families are `mi`, `vi`, `ei`). Read as
  `ansi.ei` in `tests/unit/parser.spec.ts`.

Two further notes on the constants table: the spec's `sel.u1` row
lists `k = 0.0226, c = 0.0104`, which is the transpose of SEL's
published CO-2 emulation (`t = TD * (0.0226 + 0.0104 / (M^0.02 - 1))`);
the table is implemented as written. The `abb.rd` row gives its form
as `t = a + b * ln(I/I_p)` with no constants, so it is implemented as
`t = a - b * ln(M)` with `a = 5.8, b = 1.35`, matching the prose and
the `abb.ri` row.

[[identity-and-scope]]
== Plan: identity, scoping and composition (0.3.0, breaking)

Agreed 2026-08-06, from a real six-sheet study (Bellambi Heights BESS,
five relays, two protection chains) that made three problems visible at
once. Breaking, and migrated rather than softened -- 62 of the 104
declared ids in the shipped examples contain a space, so there is no
version of this that is quietly compatible.

=== The three problems

*Identity is spelt five different ways.* A `relay` has a bare-identifier
id and a `name`; a `view` has a quoted id and a `name`; a `point` has a
quoted id and a `label`; a `fault` and a `scenario` have a quoted id and
no display key at all; `times` has a quoted id, no display key, and no
way to say anything but the id; an `annotate` has no id whatsoever.

The consequence is visible in the study that prompted this. Because
`times` has nowhere to put display text, the author put line breaks
*inside identifiers*:

  "33 kV bus primary \nclearance" { t = 200 ms; ... }

A handle you cannot retype is not a handle. It also cannot be referenced
by the scoping work below.

*Scoping exists and cannot be found.* `views = [...]` already works
uniformly -- elements, times, faults, points and annotations all pass
through `onThisSheet`. But it matches the view's `name` rather than its
id, an unknown name is silently ignored, and `view`/`views` is the only
declared-name key with no completions. The author wrote three TODOs
asking for a feature that shipped.

*Membership is enumerated where it should be derived.* Every
`views = [...]` in that study says "this relay is in the BESS chain" or
"...the auxiliary chain". The incomer's phase element lists six sheets
because it is on all of them. Inverting the direction -- views listing
their curves -- transposes the same table without shrinking it. The
relation is (chain x quantity), and the quantity half is already
derivable, which is why nobody has to list the 46 elements separately
from the phase ones.

=== Identity: id, name, description

Three tiers, identical on every declarable block, because they answer
three different questions.

`id`:: How do I refer to this? A *bare identifier*. Never displayed.
`name`:: What does the reader see? Free text, line breaks welcome.
  Defaults to the id.
`description`:: What does it mean? Prose for the legend and notes.

Bare rather than quoted so that an id *cannot* contain a space or a
newline. Discouraging that was not enough; the study proves it.

Changes: ids become bare on `fault`, `scenario`, `view`, `point`,
`device` and `times` entries; `name` is added to `times`, `fault` and
`scenario`; `label` becomes an alias of `name` on `point` and
`annotate`, warned; `annotate` gains an optional id so it can be
referenced. `title` and `subtitle` stay view-only -- a sheet heading is
a third thing, not a display name.

A quoted id at a declaration site is an error that quotes the
identifier to write instead, so the migration is discoverable from the
tool and not only from the release notes.

=== Scoping: derive, then declare, then override

One mechanism in three tiers, applied in order and stated normatively
so it cannot drift.

. *Derived.* Quantity is never written for scoping: it is read from how
  the thing is declared. A time anchored `at_I2` belongs on
  negative-sequence sheets; a point declaring `I0` belongs on
  zero-sequence sheets; an annotation naming two elements belongs
  wherever *both* are drawn.
. *Declared* -- `group = ...`. The one thing that cannot be derived
  without topology: which chain a free-floating time, point or span
  belongs to.
. *Override* -- `views = [...]`. The escape hatch, winning over both,
  for genuine exceptions such as a phase element appearing on an `I2`
  sheet as backup.

Absent everything means every sheet, so nothing already written changes
meaning.

=== Groups contain devices; everything else names a group

A group is an *ordered* set of devices -- that is what a protection
chain is, and the order is what will enumerate grading pairs when
topology lands. A time is not part of a chain; it is a requirement
about one.

So membership flows one way. A group lists devices. Times, points and
annotations *name* a group and are never listed by one. Allowing both
directions is exactly the dual reference this design exists to avoid,
and it would require inventing a precedence rule between two mechanisms
that mean the same thing.

=== A single sheet: write it there

For something that belongs to exactly one sheet, a reference is a name
kept in sync for no reason. `times`, `point` and `annotate` may be
declared *inside* a `view`, where dual referencing is impossible by
construction and there is no name to spell or rename.

Elements may not. A relay element is a real setting in a real device --
it exists whether or not it is drawn, and nesting it would put one
relay's settings in three places. The rule is worth stating in the spec
because it explains the asymmetry: *things that exist in the world are
declared where they live; things that exist only to be drawn may be
declared on the drawing.*

A nested item may not carry `group` or `views`. It is already scoped by
where it sits, and writing both is an error rather than a precedence
puzzle.

The cost, stated honestly: two legal homes for a `time` means a reader
looking for one has two places to look, and promoting a nested time to
top level is a copy-paste rather than a rename.

=== Ranges and sequence components (done 2026-08-06)

`I_min` / `I_max` on a `fault` are declared in *phase* amps and
converted by the fault's `type`, so one range sweeps correctly on a
phase sheet, an `I2` sheet or a `3I2` one. A `two_phase` fault ranged
1.2-3 kA is checked at 693-1732 A on an `I2` axis, which is the
sequence-ratio table earning its keep. Nothing per-component has to be
written and nothing can drift.

Both gaps are now closed. Every component takes `_min` / `_max`, on a
`fault` and on a `scenario`'s `level` alike, and an undeclared one is
carried across from phase *by the factor this condition's own numbers
give* rather than by the fault type's ideal ratio -- so a range always
contains the centre it surrounds. A range without its centre is
refused, since the graded point and the sweep would come from two
different sources.

Doing it uncovered a third fault, worse than either: a range endpoint
substituted the phase minimum and left every *declared* component at
its centre, so both ends of the sweep landed on the middle. Any study
declaring a component got a range check that printed two rows and
checked nothing.

=== Diagnostics this needs

Each of these is currently silent.

. A `views` entry naming no declared view.
. An annotation whose endpoints are drawn on no common sheet.
. A `group` and a `views` on the same item -- the override wins, and
  the other is dead text.
. A quoted id at a declaration site, with the identifier to use.
. An id that would collide after migration.

=== Documentation

`docs/guide.adoc` keeps its budget and its job: get a sheet drawn,
read the diagnostics. It is at 64,015 of 64,000 bytes and has turned
away three additions in two days, which is the constraint working --
the test's reasoning is that the guide stays a digest rather than a
second copy of the spec.

Composition is not digest material. A new `docs/advanced.adoc` takes
identity and references, scoping and precedence, groups and chains,
what may nest and why, multi-sheet studies, and the SVG layer contract
that is currently spec-only. It needs the same discipline or it becomes
a dumping ground: its own size budget, every code block parsed by the
suite, and one worked example per case.

=== Migration

Deterministic and lossless, so a script does the whole corpus:

  faults { "Bus fault" { ... } }   ->  faults { BUS_FAULT { name = "Bus fault"; ... } }
  grade  { fault = "Bus fault"; }  ->  grade  { fault = BUS_FAULT; }

Prose becomes a `name`, so nothing a reader sees changes -- which the
visual baseline proves sheet by sheet. Collisions after normalisation
are reported rather than resolved. Shipped as `--migrate` on the CLI,
following `scripts/migrate-ptc.mjs`.

== Current state and outstanding work

Reconciled 2026-08-06 against the tree at `a08fd56`. 1,838 tests, clean

=== Landed since the 0.1.0 plan

* *Sequence currents.* Each element grades against the current it
  measures (`quantity.ts`); `scenario` blocks declare a condition per
  level so nothing is referred across a delta; `zero_sequence` is
  declared rather than assumed.
* *Conditions on the drawing.* Scenarios draw their own rules;
  `annotate` and `point` reference conditions; `times` declares
  required clearances as horizontal rules.
* *Sheets.* Several named `view` blocks per study, each with its own
  title; `--view` / `default = true` select one without the playground.
* *Margins.* Time margins (vertical) and current margins (horizontal,
  as a percentage) to a curve, a condition or a marked point; stage
  references (`R_850:46/energ`).
* *Units everywhere* (0.2.0, breaking). No key naming a physical
  quantity carries its unit; every old spelling is refused with its
  replacement. See the revision history.
* *Help.* `?` completions everywhere; a docked help panel that
  resolves dotted identifiers such as `iec.si`.

=== Outstanding, most serious first

Reconciled 2026-08-06 after a three-part review -- usability, language
capability, and output/integration -- each conducted against a running
build rather than against the source alone. Findings below are marked
[VERIFIED] where they were reproduced directly, and [REPORTED] where
they rest on the review's own evidence and have not been re-run here.

The ordering principle is the project's own: a wrong answer given
confidently outranks a missing feature, and a promise the documentation
makes that the code breaks outranks a promise never made.

==== Silently wrong answers

. *Cross-voltage referral is ratio-only and understates the HV current
  by 15.5% for a phase-phase fault through a delta-star.* [REPORTED]
  `semantics/xvoltage.ts` applies `I x V_from/V_to` unconditionally.
  This holds for sequence magnitudes; the delta-side phase currents for
  a star-side two-phase fault distribute 2:1:1, so the largest HV phase
  is `2/sqrt(3)` times the ratio referral. The backup therefore looks
  slower than it is on the standard minimum-fault check. A `scenario`
  with declared per-level figures is a correct workaround and nothing
  says so.

==== The playground and the CLI

Reconciled 2026-08-07. The five findings this section opened with are
closed: the sheet is stamped and the exports are gated on the same
count the CLI uses, diagnostics carry real locations and drive a lint
gutter, `info` findings appear in both, and a pair that could not be
evaluated reports `unevaluated` rather than a failure. What is left:

. *The report prints `no-op s`* -- a non-finite branch returning a word
  where callers append a unit (`grades.ts:1089`).

==== Documented, and absent

Each of these is a promise the documentation makes that the code
breaks. They want one decision: implement, or delete the claim.

. *The device catalogue is dead code.* [VERIFIED] `constants/catalog.ts`
  holds eight sourced entries and `grammar.adoc` publishes a normative
  shorthand table with an equivalent expansion. `lookupCatalog` and
  `isKnownShorthand` have no callers outside their own module; the
  shorthands produce `DEVICE_NO_CURVE`. The spec table also names
  `tx_25mva_11kv` where the code key is `tx_25mva_33_11kv`.

. *`view { axis = "multiples" }` is a no-op.* [VERIFIED] `axisMode` is
  read once in `renderer/svg.ts` and thereafter only compared to
  `'secondary'`. `semantics.adoc` names it as the answer to
  cross-voltage plotting and `guide.adoc` repeats it; the same study
  renders byte-identically with `multiples` and with `primary`.

. *`two_axes` is parsed, validated, documented two contradictory ways,
  and rendered by nothing.* `semantics.adoc` calls it a secondary
  *horizontal* axis; `guide.adoc` calls it a repeat of the *time* scale
  on the right-hand edge.

. *Device-model generation does not exist.* `semantics.adoc` promises
  transformer damage points generated from `rating_S` / `rating_V` per
  C57.109, and recloser `number_of_shots` / `reclosing_time_s`
  metadata. All are `UNKNOWN_KEY` or `DEVICE_NO_CURVE`.

. *Dead settings offered in completions.* `directional`, `char_angle`,
  relay `direction` and `system { I_base }` are parsed, stored and read
  by nothing. Either mark them informational on the sheet, or remove
  them as `frequency_Hz` and `grounding` were. `I_base` belongs with
  the multiples axis above.

. *`linting-rules.adoc` states 13 rules as processor behaviour*; two
  are implemented. Five codes named in the spec are never emitted;
  around forty implemented codes appear nowhere in it.

==== Output and integration

Reconciled 2026-08-07: exit status `3`, `--json`, PDF pagination,
`--all-views` and the `[page]`/`[of]` macros are done. What is left:

. *The PDF still forces `theme: 'light'`*, discarding a declared
  `monochrome` or `print`; non-WinAnsi text is silently substituted
  (`Lodz` with its diacritics becomes `?od?`); and there is no
  document metadata and no embedded fonts, so it is not archival.

. *Extra CLI arguments are silently discarded.* [VERIFIED 2026-08-07]
  `check a.ptc b.ptc` reads only the first and exits 0. No stdin, no
  stdout, no glob, no `--watch`.

. *The sheet never says whether the study passed.* The verdict lives
  only in console output that does not travel with the file.

. *No physical size on any output.* No `pHYs` chunk in the PNGs;
  px-only SVG root. An A3 study lands in a document at 740 mm wide.

. *`--size` with an unknown keyword silently yields A4*, where the
  study path correctly raises `PAGE_SIZE_UNKNOWN`.

. *The `--force` NOT VALID stamp carries no `data-layer`*, being
  appended by string surgery on `</svg>`. A layer-aware consumer
  recomposing the sheet drops the one mark saying it is invalid.

. *`process` is exported at top level* (`index.ts`), shadowing the
  global in any module that imports it by name -- the CLI has to alias
  around the project's own export. Internals (`lex`, `tokenize`,
  `levenshtein`, `readNumber`, ...) are exported with no version
  discipline, and there are no subpath exports, though `renderer/sheet.ts`
  exists precisely because importing the barrel drags in the Node PNG
  exporter.

. *`[date]` resolves at render time* [VERIFIED], so the same study
  renders differently on different days -- narrower than the
  determinism guarantee stated in `renderer/svg.ts`. No shipped example
  uses it, so the baseline is unaffected. Prefer `meta.date` or honour
  `SOURCE_DATE_EPOCH`.

. *No `<title>`, no `role="img"`, no `aria-label` on any sheet*, and
  the one `<desc>` is a self-closed data carrier with no text -- worse
  than absent, since a screen reader announces an empty string.

. *Palette CVD claims cannot be reproduced.* `renderer/theme.ts` cites
  `scripts/validate_palette.js`, which does not exist [VERIFIED], so
  neither CI nor a reader can check them. The stated metric is worst
  *adjacent* delta-E, but adjacency in palette order is not adjacency
  on a drawing: an independent check put slots 0 and 6 of the dark
  palette at delta-E ~ 2.2 under protanopia, and tritanopia is not
  covered at all (worst all-pairs ~ 1.1-1.5 across the three palettes).
  Bounded by dash encoding and legend naming, so real but not acute.

==== Opportunities, ranked by value to a practising engineer

. *Topology is the missing concept.* Nothing says which device is
  upstream of which, or what a transformer is beyond two voltage names.
  That single absence forces the pairwise `grade` explosion -- a
  ten-relay feeder across three configurations, phase and earth, is
  around sixty hand-written blocks kept in sync by hand -- and blocks
  vector-group correctness and generated damage curves alike. An
  equipment layer (`transformer`, `cable`, `chain`) with the present
  pairwise `grade` retained as the escape hatch.

. *No arithmetic and no named constants.* `I_pickup = 1.25 * 262.4 A`
  is a lexer error. Engineers set from a multiple of full-load current,
  so today the reasoning lives in a comment and never re-derives when
  the rating changes. A `let` binding, the four operators, and an
  `flc(S, V)` builtin.

. *`grade` has the right shape and the wrong granularity.* A list of
  conditions per grade, and a `chain` declaring radial order so pairs
  enumerate themselves. `grade { fault = [...] }` currently parses and
  silently drops both entries.

. *CTI is atomic where practice is compositional.* Breaker interrupting
  time, relay overshoot, CT error, timing tolerance and safety, summed
  and reported in parts; and IDMT tolerance bands drawn on the sheet.

. *Missing device models:* thermal replica (49, IEC 60255-149 -- a
  closed form that fits the existing `CurveForm`), voltage-controlled
  and voltage-restrained overcurrent (51V), a CT model with knee-point
  and ALF, and autoreclose sequences -- which is the one place `reset`
  and `t_reset` stop being decorative and become load-bearing.

. *Curve families engineers will look for:* GE/Westinghouse IAC and the
  CO-2 to CO-9 electromechanical families, which are exactly what a
  retrofit study grades against. Also `G_D` is documented as off for
  every standard curve with per-element override deferred, so above
  M ~ 20 every IDMT curve is drawn unclamped.

. *`share` is capped at 100%*, so a current magnification -- a
  delta-star distribution factor, parallel-transformer inrush, a CT
  ratio error -- has no expression but a hand-computed scenario. Wants
  a `factor` with no upper bound alongside it.

. *Auto-scale blows the current axis out when any element has a
  definite-time high-set.* The twenty-times-pickup widening is right
  for an IDMT curve and meaningless for a shelf, which carries no
  information above pickup. Half the sheet comes out empty.

. *A settings group*, so a study comparing as-found against proposed
  does not duplicate the whole relay.

. *Onboarding: a "Try this" button on each guide code block*, loading
  the snippet into the editor. The tutorial says "paste it into the
  playground" and gives no way to; thirteen steps become thirteen
  one-click experiments.

. *Report as a deliverable:* a header naming the study, a summary line,
  and `--report-format text|markdown|csv|json`. The monospace alignment
  collapses when pasted into a proportional font.

. *Diagnostics the tool could give and does not:* naming the swapped
  primary/backup on an all-negative margin (the guide already tells the
  reader this; the message does not), and suppressing `STAGE_NO_CURVE`
  when a `curve` key was written but unresolved -- currently a curve
  typo yields two errors, one of them untrue.

==== Smaller, and worth doing when nearby

. *A pinch on the plot zoomed the page on iOS.* Reported as losing the
  toolbars on mobile. `touch-action: none` is enough for Chrome, which
  reads it as "this element handles its own gestures"; WebKit does not
  apply `touch-action` to pinch-zoom at all, so a pinch on the plot
  zoomed the whole application and carried the toolbars off the side of
  the visual viewport. `touchstart` now claims a second finger the
  moment it lands, and Safari's `gesturestart` / `gesturechange` /
  `gestureend` are intercepted and drive the display scale from the
  cumulative `scale`. *Not verified on a device* -- there is no iOS
  Safari in this environment -- but it is the documented remedy and
  the handlers are exercised in test and in a browser.

  Width alone was ruled out first: the split was swept from 1600 px to
  400 px in both modes and all three pane states, and 22 of 22 toolbar
  buttons stayed reachable.

. *`svg.ts` decomposition.* One large function holding around forty
  closures. Split in this order or the captures merely move: sheet
  model, legend, annotations, frame.

. *Range sweep does nothing for sequence elements* but still prints a
  range-check table implying it ran.

. *Ctrl+S is bound to Download, not to the button labelled Save*, and
  no shortcut is documented outside the source.

. *No time-axis zoom, and pan is middle-drag only* -- so inspecting
  whether a 0.30 s margin is met near 0.3 s means editing the source.
  The plot is not keyboard-reachable at all.

. *A share link pasted into an already-open tab does nothing*: the
  fragment is read only in `connectedCallback`, and there is no
  `hashchange` listener.

. *A study opened from a link with no `meta` block is labelled as an
  unrelated example* in the picker.

. *`examples/03-mixed-ansi-iec.ptc` ships a `MARGIN_NO_SOLVE` warning
  and a grade that cannot be evaluated*, and it is fourth in the
  picker.

. *The report panel opens above the whole application*, unstyled,
  shrinking the plot it describes.

. *All three components carry a `static styles` block that is never
  applied.* They render into the light DOM (`createRenderRoot` returns
  `this`), and Lit adopts `static styles` only into a shadow root --
  so around 200 lines in `tc-viewer`, and more in `tc-editor` and
  `tc-app`, are dead. The live rules are `src/styles/global.css`, which
  largely duplicates them. It reads as the place to edit and silently
  is not: two rules were added there during the mobile work and had no
  effect. Either delete the blocks or move the sheet into them, but the
  present state is a trap.

. *PNG/PDF export can abort the process* on at least one valid study
  via a native resvg panic; the reviewer preserved a repro but did not
  isolate the trigger. Worth running the rasteriser out of process so a
  panic is an error rather than a killed CLI.

. *Band hatching is ~175 stroked lines per band behind a clip path.*
  An SVG `<pattern>` would be one element and clip-independent; some
  importers drop `<defs>` and spray hatching across the sheet.

. *PDF wrapping is computed against the monospace advance* and then set
  in proportional Helvetica, so legend lines break early. Nothing
  overflows -- the substitution is strictly narrower -- just loose.

=== Closed 2026-08-06

* *A pane chosen on a narrow window rewrote the wide layout.* The
  narrow Source/Plot switch and the wide Hide/Split buttons wrote the
  same field, so zooming in until the window went narrow, tapping
  `Source`, and zooming back out left the plot hidden -- a layout the
  reader never asked for, restored only by finding a button whose
  label had also changed. The narrow choice now lives in `narrowPane`
  and is not stored; arriving narrow it is seeded from the wide
  layout, and re-seeded only on the transition.

* *The legend's notes cost the reader the settings.* Notes were drawn
  at any density above `minimal` and the only way to buy space was to
  drop a density -- which also drops every relay's settings. So a
  sheet with eight curves and twenty notes showed no settings at all,
  and turning the notes *off* was how you got them back. Worse, the
  fallback landed on `minimal`, which draws neither: the space the
  notes forced was then spent on nothing. Notes are now a separate
  axis of the fit, tried after detail is preserved, and where they do
  not fit they are reduced to a count and a pointer to the report
  rather than dropped in silence. Sample 17's 3I2 sheet was itself a
  victim -- it had been drawing at `compact`, without maker or
  voltage lines, and now draws in full.

* *Major and minor gridlines were one grey field.* They differed by
  weight alone -- 0.9px against 0.6, full against 70% -- on an axis
  that draws nine lines per decade, so finding a decade meant counting.
  Minor lines are dotted by default now, and `page { axes }` takes
  `grid_minor_color`, `grid_style` and `grid_minor_style`.

* *`[page]` and `[of]` never resolved.* The spec said the exporter
  paginates; nothing did. `exportPdfSheets` binds every declared view
  into one PDF -- `render --pdf --all-views`, and a `PDF (all sheets)`
  button in the playground when a study declares more than one -- and
  passes each sheet its own `pagination`.

* *`docs/skill.adoc`*, a fourth in-app document ("For an AI"). Written
  to be handed to an agent along with a setting report: the two rules
  that matter (write only what the report says; then run the
  validator), the smallest useful study, a report-to-language mapping
  table, and a decision ladder that says when to *stop* adding
  language. Its blocks are parsed and its starter study is graded by
  `tests/unit/skill.spec.ts`.

* *`current_max` was ink and nothing else.* It was read where a curve
  was *drawn* and ignored everywhere a number was computed, so a
  high-set blocked above the maximum through-fault was drawn stopping
  at its ceiling and then evaluated well past it -- `tTripElement` is a
  plain min over stages and had never seen a cutoff, so the composite
  returned the blocked stage's 50 ms at twice the current and the grade
  report printed it. Measured at 10 kA against a 5 kA cutoff: 0.05 s
  reported where the surviving stage gives 0.42 s, eight times fast.
  A stage now does not operate past its cutoff, a combined curve stops
  where its sources stop, and a grade asked for beyond a curve's end is
  `GRADE_BEYOND_CUTOFF` rather than a number. Renamed `I_cutoff` in the
  same pass, because `current_max` also means an axis bound on a
  `view` and one spelling was carrying two concepts.

* *An error-severity grade diagnostic reached nothing.* Grade reports
  carry their own diagnostics and they were printed inside the text
  report only -- not in `result.diagnostics`, so not in the CLI's exit
  code and not in the playground's error count. `check` exited 0 on a
  study it had refused to grade. They are hoisted now; no shipped
  example changes status.

* *The plot pane was never measured.* `firstUpdated` attached the
  `ResizeObserver` to `div.pane-host`, which does not exist on that
  update -- the viewer is still showing its empty state -- so the guard
  returned and nothing ever tried again. Every sheet in the playground
  was therefore laid out at the hardcoded 1500x1000 default whatever
  size the pane actually was, and no amount of resizing changed it.
  Attaching from `updated` instead means it binds on the update that
  first draws a plot. Confirmed in the browser: `ro` was `undefined`
  before, and the sheet now tracks the pane.

* *The drawing could not be made larger.* The sheet was CSS-sized to
  `100%` of the pane, so a narrow screen squeezed a 960px layout into
  390 -- 61%, which renders 11px legend text at under 7px -- and the
  only zoom gesture there was moved the *axes*, re-laying the sheet out
  at the same size. So no gesture existed that made the text bigger.
  The pane now scrolls a full-size drawing, `displayScale` sizes it,
  the toolbar carries -- / Fit / 1:1 / +, and a touch pinch drives the
  scale while one finger moves the paper. Auto-fitting a narrow pane
  was tried and dropped: it reproduces the complaint exactly, clamping
  a phone to 0.3 where the drawing is a smudge. `Fit` is one tap away
  for a reader who wants the overview.

* *The drag and the wheel now say which zoom they mean.* Middle-drag
  moves the paper when the drawing is larger than the pane, in both
  axes -- the domain pan was horizontal only, so a sheet the display
  zoom had made taller than the pane had no reachable bottom. And the
  wheel sizes the drawing when the pointer is off the plot rectangle,
  where there is no current under it to anchor an axis zoom to;
  wheeling out there stops at the default rather than the floor,
  whichever is smaller of actual size and the fit scale. On the plot
  the wheel is unchanged.

* *A stage reference in `grade` was ignored and the composite graded.*
  `resolveRef` dropped `stageId`; only the renderer honoured it, so the
  sheet drew the stage that was named and the report graded something
  else. The narrowing moved into `resolveRef` and the renderer's copy
  was deleted. A stage name matching nothing was also silent, and is
  now `UNRESOLVED_STAGE`; giving that diagnostic somewhere to point
  gave `Ref` a source location, which two combine diagnostics now use.

* *Device tables were not validated at all.* An element's `flex_points`
  were checked and a device's three tables were not, so a fuse could
  declare a repeated current or a one-row band and validate clean. One
  checker now serves both. The reported version of this finding -- that
  unsorted tables are silently mis-evaluated -- was wrong: `buildStudy`
  sorts every table before anything reads it, and a test now pins that.

* *The upstream sweep judged studies at impossible currents.* Its
  ceiling was the largest of the declared fault, twenty times pick-up
  and twice the start, and it referred faults across voltage levels --
  so an 18.4 kA fault on a 33 kV bus became 55.2 kA on the 11 kV feeder
  below it. The ceiling is now the largest fault declared at the
  primary's own level and nothing more.

* *The sweep now runs by default*, the ceiling being trustworthy. Of
  the shipped examples only sample 07 fails, which is its purpose;
  sample 11 needed a genuine setting change (its bus relay graded at
  0.22 and converged 26 ms short at 13.5 kA) and sample 10's spur fuse
  declares `upstream = false`, because a fuse at the end of a spur
  cannot carry the busbar fault and nothing in the language says so.
  The empty-range warning is now raised only where the sweep was asked
  for explicitly, since grading at a study's largest fault is the
  normal case and would otherwise warn on most sound studies.

  That last point is the interesting residue: the sweep bounds itself
  by *voltage level* because voltage level is all the language knows.
  Position on the network -- which device is downstream of which -- is
  the missing concept, and it is the same absence that forces the
  pairwise `grade` explosion.

=== Closed 2026-07-31

* *The formatter lays blocks out verbosely.* It was line-based and never
  *split*, so a nested value block written inline stayed inline and the
  `=` alignment could not help it -- alignment works down a column and
  there was only one line. An explode pass now gives each brace and each
  statement its own line before indenting. Brackets are left alone: a
  `[` list is a value, and `flex_points` tables are read as rows.
  `expandBlocks: false` keeps the old behaviour. Still idempotent and
  still meaning-preserving over every shipped example, which the
  existing property tests check.

* *Cross-voltage curve placement contradicted the report.* A curve from
  another level was positioned by the turns ratio for the voltage and
  then by the condition's ratios for the quantity, and the two
  disagree behind a delta. Where the named condition declares figures
  at both levels a curve is now placed from that condition alone, one
  factor for both, and no referral happens; where it declares only one
  the turns ratio still applies, unchanged. Verified by measuring the
  rendered sheet: example 12's LV breaker now crosses the fault rule
  at 1.631 s, the time its own report gives. Four cross-level examples
  render byte for byte as before.
* *Everything the sheet refers by the turns ratio now says so where
  the ratio does not hold.* The over-claim was never confined to
  curves: six sites gate on `survivesVoltageReferral`, which waves
  phase current through unconditionally. All six -- fault rules,
  scenario rules, marked points, annotations, condition currents and
  the curve fallback -- go through one helper, so the sentence is
  worded once and cannot drift between them. It fires only where
  `zero_sequence` is declared `blocked` and the condition is
  unbalanced; a balanced fault refers correctly and gets no note.
* *Page-cosmetic keys keep their unit in the name*, by decision. The
  spec states it as an exception with the reasoning rather than
  leaving it to look like an oversight.

* *`abb.ri` operated in 0.000 s above `M ~ 4.3`.* The row carried RD's
  constants in a linear form. Replaced with the published hyperbola,
  which has no zero crossing. Separately, a characteristic that runs
  out of definition (RD above `M ~ 73.4`) now reports no operation
  rather than clamping to zero -- zero being the fastest answer
  available, asserted exactly where the curve stops saying anything.
* *The pass/fail verdict was thinly tested.* The boundary was the real
  hole: swapping `>=` for `>` in the margin comparison changed no
  test's outcome, though a study graded to sit exactly on its declared
  minimum is what `solve` produces. `tests/unit/verdict.spec.ts` pins
  the boundary, both directions, the absent-requirement case and the
  printed verdict; all three mutations tried against it now fail.
* *Every parser error was reported twice.* `Parser` was handed the
  lexer's array and assigned it to `this.errors`, so the two names were
  one object and `parse` spread both. Copied in instead.
* *`faults` could not declare `I1`*, while the unknown-key list already
  named it as accepted -- so a declared `I1` warned about nothing and
  was discarded. Wired through the parser, AST, model and condition
  resolution.
