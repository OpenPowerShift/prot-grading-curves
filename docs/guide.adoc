A practical guide to writing `.ptc` files: protection-relay time-current
grading studies as plain text.

This document is self-contained and example-led. It is the reference to
read (or to give a language model) when *authoring* a study. The
normative specification -- grammar productions, curve constant tables,
conformance requirements -- is a separate document, `spec/spec.adoc`;
where the two differ, the spec wins.

toc::[]

== Before anything else

A `.ptc` file declares four things and asks one question:

. the *voltage levels* in the study,
. the *fault currents* (or scenarios) the study is judged against,
. the *relays* and their protection elements,
. the *grading pairs* -- which element must clear before which other.

The tool then computes each element's time-current characteristic,
checks every pair's coordination time interval (CTI), and draws the
log-log plot.

It does not compute fault levels. Short-circuit currents are input
data, taken from your network study.

=== A complete file

Every construct below is optional except `relay` and `element`. This is
a working study:

[source,tc]
----
meta {
    project   = "Riverside 33/11 kV";
    engineer  = "A. Cooper";
    date      = "2026-07-30";
    margin    = 0.30 s;              # default grading interval
}

system {
    voltages {
        "HV" { V  = 33.0 kV; }
        "LV" { V  = 11.0 kV; }
    }
}

faults {
    "F_lv_max" { I   = 6400 A;  voltage = "LV"; }
    "F_hv_max" { I   = 18400 A; voltage = "HV"; }
}

relay R_FDR {
    name     = "Feeder 4";         # free text for the drawing
    voltage  = "LV";
    ct_ratio = 600/5;

    element 51 {
        function = "phase_oc";
        curve    = iec.si;         # IEC standard inverse
        I_pickup = 480 A;
        tms      = 0.30;
    }
}

relay R_INC {
    voltage  = "HV";
    ct_ratio = 600/5;

    element 51 {
        function = "phase_oc";
        curve    = iec.si;
        I_pickup = 720 A;
        tms      = 0.175;
    }
}

grade {
    primary   = R_FDR:51;          # must clear first
    backup    = R_INC:51;
    fault     = "F_lv_max";
    margin    = 0.30 s;
}

view { voltage = "HV"; }           # draw everything in the 33 kV frame
----

=== Finding out what something means

Two ways, both in the playground:

* **`?` or Ctrl-Space** while writing: on a blank line it lists what
  the enclosing block accepts; after an `=` it lists that field's
  values -- curve names, quantities, the conditions and voltage levels
  the file itself declares.
* **The help strip** under the source while reading: put the caret on
  anything and it explains it, including named values like `iec.si`.
  Docked rather than floating, because a tooltip covers the line you
  are reading -- which is exactly the line you were asking about. Shut
  it with the `x` and it stays shut; the *Help* button brings it back.
* **Hovering the plot**: the readout names what the cursor has latched
  onto and, beneath that, the *reference* a `grade` or an `annotate`
  would use. Those differ as soon as anything declares a `name` -- a
  curve drawn as "11 kV feeder · Phase TOC" is written `R_FDR:51` --
  and the reference is the one you can type. Faults, marked points and
  annotations answer with their declared names, which are already
  their references.
+
Where several curves lie on the same spot -- two feeders set
identically, a composite and the stage that forms it -- *all* of them
are named, not whichever the tool happened to find first.

=== Running it

[source,bash]
----
tc-curves check  study.ptc              # parse + validate only
tc-curves report study.ptc              # margin report to stdout
tc-curves render study.ptc --svg -o study.svg
tc-curves render study.ptc --png -o study.png --width 1600
tc-curves render study.ptc --pdf -o study.pdf
----

== Syntax essentials

* Blocks are `keyword { ... }`; statements inside end with `;`.
* Comments: `#`, `//`, and `/* ... */`.
* Strings are double-quoted. Escapes: `\"`, `\\`, `\n`, `\t`,
  `\u{XXXX}`.
* **`\n` breaks a line on the drawing.** It works in any text the
  sheet renders -- a `label` on a point or an annotation, a `times`
  name, a `title`, a `subtitle`, a legend `comment` -- and is how a
  long caption is kept from running across the plot:
+
[source,tc]
----
times { "ph-g/ph-ph total clearance\nafter energisation" { t = 430 ms; } }
point "Inrush" { I = 2 kA; t = 100 ms;
                 label = "Inrush falls below\n50P pickup, 184 ms"; }
----
* Numbers take a `_` group separator: `18_430` is `18430`.
* **Units are required** wherever the field is not unit-free. A bare
  number in a unit-bearing field is a parse error.

=== No key carries its own unit

Every field takes the unit from you, and checks it:

[source,tc]
----
system { voltages { "HV" { V = 33 kV; } } }
faults  { "Bus max" { I = 6.4 kA; voltage = "HV"; } }
relay R { element 51 { I_pickup = 480 A; tms = 0.3; t_delay = 60 ms; } }
grade   { primary = R:51; backup = R_INC:51; margin = 0.3 s; }
----

`I` is phase current, `I1` / `I2` / `I0` the components, `residual`
the `3*I0` stated directly; `V` a voltage, `t` a time. The same
vocabulary in a `fault`, a `scenario` level, a `point` and an
`annotate`, so one current is written one way everywhere.

The old unit-carrying spellings -- `I_A`, `t_s`, `kV`, `CTI_min_s` --
are still recognised, and each is refused with its replacement rather
than looking like a typo.

=== Units

[cols="1,3", options="header"]
|===
| Quantity | Suffixes

| Current | `A`, `kA`, `mA`
| Pickup, extra forms | `A_sec` (secondary amps, multiplied by `ct_ratio`), `A_pri` (primary, explicitly), `pu`, `xCT`, `xIn`
| Time | `s`, `ms`, `min`
| Voltage | `kV`, `V`, `MV`
| Power | `MVA`, `kVA`, `GVA`, `MW`
| Angle | `deg`
|===

`A_sec` is how a settings sheet reads. These are the same element:

[source,tc]
----
element 51 { I_pickup = 5.0 A_sec; }         # x ct_ratio -> 600 A primary
element 51 { I_pickup = 600 A; }             # same, stated as primary
element 51 { I_pickup = 5.0 A; I_units = "secondary"; }   # older spelling
----

`A_pri` exists so one primary figure can sit inside an element
otherwise dialled in secondary amps.

=== Two errors worth knowing

`DUPLICATE_KEY`:: A key assigned twice in one block.

`MISSING_VALUE`:: An `=` with nothing after it.

`UNKNOWN_SETTING`:: A name inside an `element` the language does not
know -- `tsm` for `tms`, which would leave the element at its default
and the margin out by a factor of ten.

`UNIT_UNKNOWN`:: A suffix outside the table below. They are
case-sensitive: `kA`, not `KA`; `ms`, not `msec`.

== Identifiers

*Relay ids* are letters, digits, underscores, starting with a letter or
underscore: `R_FDR_1`, `R_INC`.

*Element ids* are IEEE C37.2 device numbers and may start with a digit
and carry a letter suffix: `51`, `50`, `51G`, `67N`, `51X`, `87T`.

*References* are `relay:element` -- `R_FDR_1:51`, `R_850:51G`.

*Curve ids* are lower-case and namespaced: `iec.si`, `ansi.mi`.

`name` is separate from the identifier. The id is what references
resolve against; `name` is free text shown on the drawing, so renaming
for a reader never breaks a reference:

[source,tc]
----
relay R_INC {
    name = "Incomer 11 kV, panel 3";
    element 51 { name = "Phase OC (main)"; ... }
}
grade { backup = R_INC:51; }        # still the identifier
----

== Blocks

=== meta

Project identification. Open-ended; these keys are read by the title
block and the `[meta.*]` footer macros:

[source,tc]
----
meta {
    project   = "Northgate 11 kV";
    study     = "Feeder grading";
    engineer  = "A. Cooper";
    date      = "2026-07-30";
    revision  = "B";
    reference = "DOC-1234";
    margin    = 0.30 s;          # default for grade blocks that omit it
}
----

=== system

[source,tc]
----
system {
    voltages {
        "HV" { V  = 33.0 kV; description = "33 kV switchboard"; }
        "LV" { V  = 11.0 kV; }
    }
    base_S       = 25 MVA;
    I_base       = 1000 A;         # the 1.0 pu current, for `pu` pickups
    I_units      = "primary";      # study-wide default for pickups
}
----

Voltage levels are named, and the processor derives turns ratios from
them. There is deliberately no transformer block.

`I_base` is what `1.0 pu` means. A pickup written `I_pickup = 1.2 pu`
is resolved against it, which lets a settings sheet quoted in per-unit
be transcribed as written rather than converted by hand -- and the
conversion is then in the file for the next reader to check.

=== faults

One current at one level:

[source,tc]
----
faults {
    "F_lv_max" {
        I           = 6400 A;
        I_min       = 4000 A;      # sweep the CTI check across a range
        I_max       = 8000 A;
        voltage     = "LV";
        description = "Busbar 3ph, system normal";
    }
    "F_lv_earth" {
        I       = 6400 A;
        I0      = 800 A;           # zero-sequence component
        I2      = 800 A;           # negative-sequence component
        residual = 2400 A;          # residual 3*I0, if you prefer
        voltage = "LV";
    }
}
----

`I` is the *phase* current. `I0` is the component `I0`; `residual`
is the residual `3*I0` stated directly. Declare either -- the processor
derives the other, and errors if you declare both inconsistently.

That check applies wherever the pair can be written: a `fault`, a
`scenario` level, a `point`, and an annotation's `at_I0` / `at_residual`
-- and on a fault, at each end of a declared range as well as at its
centre. Nothing reconciles a contradictory pair, because nothing can:
`I0` is read from `I0` and `3I0` from `residual`, each preferring the
figure written for it, so `I0 = 300 A; residual = 450 A` would evaluate
a `3I0` relay at 450 A and an `I0` relay at 300 A *at the same earth
fault*. Which of the two figures is the wrong one is not something the
tool can work out, so it asks. A 1% tolerance keeps a rounded number
off a fault study from being called a contradiction.

If only `I` is given, `I_min` and `I_max` default to it.

[IMPORTANT]
====
`voltage` on a fault is *the level the current was measured at*, not
the level the fault is on.

They are the same thing for a fault on its own bus, which is why the
distinction is easy to miss. They are not the same when a fault on one
side of a transformer is quoted as the current seen on the other --
which is how a fault study usually reports it, because that is where
the relay and the CT are. Write the level the *figure* belongs to; the
tool refers it to whatever axis a sheet is drawn in.

Get this wrong and every current is out by the turns ratio, in a way
nothing can detect: the number is plausible and the sheet is drawn
without complaint.
====

=== times

Required clearances, drawn as horizontal rules -- the other axis's
answer to a `fault`:

[source,tc]
----
times {
    "Arc flash limit"     { t   = 200 ms; description = "PPE category boundary"; }
    "Grid code clearance" { t   = 430 ms; }
    "Bus zone backup"     { t   = 2 s; }
}
----

A study is judged against currents *and* against times: an arc-flash
limit, a transformer withstand, a grid-code disconnection time, a
bus-zone backup. Writing them down puts the requirement on the sheet
beside the characteristic that has to meet it, instead of the reader
holding the number in their head.

A time needs no voltage level -- a second is a second on every winding
-- which is the one way this is simpler than a fault. Each rule is
labelled on the plot, listed in a *Times* legend section, and
widens the time axis so a requirement can never fall off the sheet that
is meant to show it being met. One declared outside an explicit
`view { time_min / time_max }` says so rather than disappearing.

A rule spans the whole plot, so its name has nowhere obvious to sit and
goes at the left-hand end by default. `at_I` moves it to where the
reader is actually looking -- beside the curve the clearance applies to:

[source,tc]
----
times {
    "Arc flash limit" { t = 200 ms; at_I = 3 kA; }
}
----

The figure is read off the sheet's own axis. One outside the plotted
currents falls back to the left-hand end rather than writing the caption
into the margin.

`at_I` alone means *phase* current, so on a sheet drawn in `I2` or
`3I0` name the component -- `at_I1`, `at_I2`, `at_I0`, `at_residual`,
or a `type` to derive the rest -- exactly as a `point` or an
`annotate` does:

[source,tc]
----
times {
    "Earth-fault clearance" { t = 800 ms; at_residual = 1.2 kA; }
}
----

An anchor the sheet's quantity cannot resolve still draws the rule and
still writes its name, at the left-hand end -- and says so in the
notes, because otherwise it is indistinguishable from having asked for
no anchor at all.

Each rule is captioned with its name *and its current* --
`Board max · 6.2 kA`, the figure it is drawn for. Turn that off with
`page { faults = { currents = false; }; }`.

Style them with `page { times = { color = ...; width_px = ...; style =
"solid" | "dashed" | "dotted"; labels = false; }; }`, which mirrors
`page { faults }`. They are drawn in a different ink from the fault
rules by default, so it is never a question which axis a rule belongs
to.

[TIP]
====
A characteristic is defined for any multiple; the *network* is not.
Past the largest fault the bus can deliver, the curve describes a
current that cannot flow, and a margin taken off it is graded against
a fault that does not exist.

`element { I_cutoff = 8 kA; }` stops the curve there, and the legend
records the limit, so a curve that ends short reads as one that was
told to. A `stage` takes one too and falls back to its element's: a
high-set blocked above the maximum through-fault stops where *its*
data stops.

Not only ink. Past its cutoff a stage does not operate, so a composite
steps back onto whatever stage is still there, an upstream sweep stops
where the curves do, and a grade taken beyond a curve's end is refused
(`GRADE_BEYOND_CUTOFF`) rather than answered from a characteristic the
study says is not there.
====

==== Drawing one curve differently

The palette is right for an ordinary study and wrong whenever a
drawing has to match something outside itself: a house standard, a
figure whose inks are fixed by the report around it, or a curve that
is context rather than argument. `color`, `style` and `width_px` say
so, on an `element` or a `stage`:

[source,tc]
----
element 50BF {
    curve    = definite;
    I_pickup = 1.8 kA;
    t_delay  = 250 ms;
    color    = "#8a8983";          # context, deliberately subdued
    style    = dotted;             # solid | dashed | dotted
    width_px = 1.4;                # overrides curves.line_width_px
}
----

A stage inherits whatever its element declared. The palette slot is
*still consumed*, so naming a colour on one element does not shift the
hues of the others -- a sheet is read against its legend, and a study
that recolours as curves come and go makes two revisions of one
drawing impossible to compare.

A `style` the tool cannot draw is `CURVE_STYLE_INVALID`, not a silent
fallback: a solid line the source calls dashed is a drawing that
disagrees with its own file.

=== currents

`times`'s answer the other way: a rating, drawn as a vertical rule,
headed *Ratings* apart from the fault rules:

[source,tc]
----
currents { "Busbar rating" { I = 12.5 kA; at_t = 300 ms; } }
----

=== relay and element

[source,tc]
----
relay R_FDR {
    name      = "Feeder 4 (Mill Road)";
    maker     = "Schneider";
    model     = "MiCOM_P122";
    voltage   = "LV";
    ct_ratio  = 400/5;             # -> n_CT = 80

    element 51 {
        name     = "Phase OC";
        function = "phase_oc";
        curve    = iec.si;
        I_pickup = 320 A;
        tms      = 0.12;
    }

    element 50 {
        curve   = definite;
        I_pickup = 9 kA;
        t_delay = 60 ms;           # not 0 -- see the warning below
    }
}
----

WARNING: `t_delay = 0 s` has no position on the logarithmic time axis,
so it is drawn at 20 ms instead -- a plausible instantaneous operate
time, not the figure written. Enter the relay's real one, typically
10-40 ms. The diagnostic is `ZERO_DELAY_NOT_PLOTTABLE`.

==== Multi-stage elements

When one protection function has several stages, the plotted curve is
the pointwise minimum -- what the relay actually does:

[source,tc]
----
element 50 {
    function = "phase_oc";
    stages {
        stage main  { curve = definite; I_pickup = 147 A; t_delay = 40 ms; }
        stage energ { curve = definite; I_pickup = 255 A; t_delay = 20 ms; }
    }
}
----

Stage fields fall back to the element, so a pickup declared once on the
element applies to every stage that does not restate it.

=== Curves

Standard families, by namespace:

[cols="1,4", options="header"]
|===
| Namespace | Curve ids

| `iec` | `iec.si`, `iec.vi`, `iec.ei`, `iec.lti`, `iec.sti`
| `ansi` | `ansi.mi`, `ansi.vi`, `ansi.ei`
| `sel` | `sel.c1`..`sel.c5`, `sel.u1`..`sel.u5`
| `ge` | `ge.ur.si`, `ge.ur.mi`, `ge.ur.vi`, `ge.ur.ei`
| `abb` | `abb.ri`, `abb.rd`
| `siemens` | `siemens.inv`, `siemens.long_inv`, `siemens.long_vi`, `siemens.long_ei`
| `schneider` | `schneider.sit`, `schneider.vit`, `schneider.eit`
|===

Plus three non-catalogue forms:

[source,tc]
----
element 51 { curve = definite; I_pickup = 3 kA; t_delay = 100 ms; }

element 51 {                                    # your own constants
    formula = { k = 4.0; c = 0.10; alpha = 0.50; };
    I_pickup = 500 A; tms = 0.2;
}

element 51 {                                    # a published point table
    flex_points = [(240 A, 50.0 s), (600 A, 5.0 s),
                   (1200 A, 1.0 s), (5000 A, 0.20 s)];
    I_pickup = 240 A; tms = 1.0;
}
----

`flex_points` are absolute amps and seconds; `tms` scales the times
linearly. Use them for anything the catalogue does not cover -- ACB
trip units, thermal curves, manufacturer data.

==== What a time-current sheet cannot say

Directionality and the reset characteristic are real settings and this
tool records neither. `direction`, `directional`, `char_angle`, `reset`
and `t_reset` existed until 2026-08-08, were stored, and were read by
nothing; they are refused now, with a sentence saying so.

Whether an element is directional decides *which faults it responds
to*, not how long it takes at a current, so there is nothing for a TCC
to draw. That is a real limit on what a coordination sheet argues: a
parallel pair needs directional elements or a fault on one circuit
trips the healthy one, and this drawing cannot show it. Put such
settings in `description`, or in the page's `notes` block where they
appear on the sheet:

[source,tc]
----
element 51 {
    function    = "phase_oc";
    curve       = ansi.mi;
    I_pickup    = 480 A;
    tms         = 1.0;
    description = "Directional, forward, MTA 45 deg; disc reset 6 s";
}
----

=== What an element measures

A relay does not measure "the fault current". Which current the pickup
refers to decides the multiple, and so the operate time:

[cols="1,2,2", options="header"]
|===
| `function` | Measures | Default

| `phase_oc` | phase current | `phase`
| `earth_fault` | residual `3*I0` | `3I0`
| `neg_seq` | negative sequence | *none -- you must state it*
| `thermal` | RMS phase current | `phase`
| `breaker_fail` | phase current | `phase`
|===

Override with `measures`, whose values are `phase`, `I1`, `I2`, `3I2`,
`I0`, `3I0`:

[source,tc]
----
element 51G { function = "earth_fault"; }                  # 3I0 by default
element 51G { function = "earth_fault"; measures = "I0"; }  # this IED is in I0
element 46  { function = "neg_seq"; measures = "I2"; }      # required
----

IMPORTANT: `neg_seq` has no default because IEDs differ over whether
the pickup is scaled in `I2` or `3*I2`. A factor of three is the
difference between an element that operates and one that does not, so
guessing is not acceptable. Omitting `measures` is the error
`MEASURES_REQUIRED`.

If an element measures a component the referenced fault does not
declare, that is the error `SEQUENCE_DATA_MISSING` and the pair is not
graded. No other quantity is substituted -- a margin computed off the
wrong current is a wrong number that looks right.

=== scenario

A `fault` is one current at one level. Referring it to another level by
the turns ratio is correct for phase current, and for positive and
negative sequence -- but **zero sequence does not cross a delta
winding**. No ratio carries it.

A `scenario` declares one condition at every level it is measured, so
nothing has to be transformed:

[source,tc]
----
scenario "LV earth fault" {
    description = "Single phase to earth at 0.48 kV";

    # star side: the components are equal for a phase-earth fault
    level "LV" { I   = 460 A; I1   = 153 A; I2   = 153 A; I0   = 153 A; }

    # delta side: no zero sequence gets through
    level "HV" { I   = 3.9 A; I1   = 2.2 A; I2   = 2.2 A;  I0   = 0 A;  }

    sees R_FDR { share       = 50 %; }   # parallel paths: half the current
}

grade {
    primary   = R_ACB:51;
    backup    = R_850:46;              # I2 backup
    scenario  = "LV earth fault";
    margin    = 0.30 s;
}
----

This is the reason an HV *negative-sequence* element, not an HV
residual element, backs up an LV earth fault: at HV the residual is
zero, so a `51G` there is blind to the fault. Declare it and the report
says so.

`fault` and `scenario` are alternatives; declaring both is an error.

==== Scenarios on the drawing

A scenario draws its own vertical rule, at **its own figure for the
level the sheet is in** -- 153 A of residual on an LV sheet, nothing at
all on a delta-side residual sheet. Nothing is referred across the
transformer, which is the whole reason to write one. The rule stands at
the value of whatever quantity the view is drawn against, so a sheet in
`I2` marks the scenario's `I2`.

Where a scenario cannot be marked, the legend says so rather than
leaving it off quietly -- grading still reports a margin against it, so
silence would invite the reader to assume it was not relevant:

[none]
* `system normal declares no currents at LV (has HV, MV)` -- it was
  never measured on the level being drawn. A scenario declaring just
  *one* level is unambiguous and is carried onto the sheet by the turns
  ratio instead.
* `system normal carries no residual 3I0 at HV` -- the component is
  zero there, which is a real answer and has no place on a log axis.

Faults and scenarios can share a sheet. When they do, the panel is
headed *Conditions* rather than *Faults*, and each scenario entry says
`scenario` under it, because the figure came from the study's own
measurement at that level rather than from a turns-ratio referral.

[NOTE]
====
A curve belonging to another voltage level is placed from the
*condition the sheet names*, whenever that condition declares figures
at both levels. Nothing is referred: the element measures a stated
current at its own bus, the axis reads a stated current at the sheet's,
and the ratio between those two is the whole mapping -- quantity and
voltage together. The drawing and the grading report then agree by
construction rather than by coincidence.

This matters because a scenario's per-level figures deliberately need
not follow the turns ratio, and behind a delta they must not. For the
delta-star above, 460 A at LV is declared against 3.86 A at HV, where
the ratio alone would give 6.7 A. Phase current is `I1 + I2 + I0`, and
the zero-sequence third stays in the delta.

Placing such a curve by kV put it a factor of `sqrt(3)` too far right:
its pickup landed past the fault rule, so the sheet showed a breaker
that never operates while the report had the same breaker clearing the
same fault in 1.63 s and passing. One drawing, two answers.

Where the condition is silent about one of the levels -- a `fault` is
one current at one level -- the turns ratio is used, which is right for
it. If the study has declared `zero_sequence` blocked between the two
levels and the condition is unbalanced, the legend says the placement
rests on a ratio phase current does not follow, and names the one-line
fix: declare the condition as a scenario with figures at both levels.

That note covers everything the sheet places by the ratio, not curves
alone -- fault rules, scenario rules, marked points, annotations and
condition currents all refer the same way and all say the same thing
when the ratio is the wrong instrument. A balanced fault carries no
zero sequence to be blocked, so it refers correctly and says nothing.

The legend states a converted cross-level curve in full -- both levels,
the factor, and the condition it came from -- because a factor that
carries a change of level as well as a change of quantity reads as
neither on its own.
====

=== device

Fuses, cable damage curves, recloser characteristics -- anything with a
published characteristic that is not a relay element:

[source,tc]
----
device "spur_fuse_50T" {
    kind        = fuse;
    maker       = "Mersen";
    model       = "50T";
    rating_I    = 50 A;
    min_melt    = [(100 A, 100 s), (1 kA, 0.05 s)];
    total_clear = [(100 A, 200 s), (1 kA, 0.10 s)];
}
----

`kind` is one of `fuse`, `recloser`, `cable`, `transformer_damage`,
`motor_startup`, `breaker`. A fuse with both tables draws as a hatched
band. In grading it uses *total clear* as the primary and *minimum
melt* as the backup, which is the conservative reading each way.

Reference a device by its id, quoted or bare:
`grade { primary = "spur_fuse_50T"; }`.

Give it a `voltage` if the study spans more than one level. A published
fuse curve is in the amps of the winding it sits on, so without a level
its points are taken as already being in the view frame -- and on a
cross-voltage sheet the band is drawn out by the turns ratio. This is
not `rating_V`, which is the fuse's own insulation rating:

[source,tc]
----
device "spur_fuse_50T" {
    kind      = fuse;
    voltage   = "LV";        # the level it sits on
    rating_V  = 12 kV;       # its insulation rating -- a different thing
    rating_I  = 50 A;
    rating_S  = 1.25 MVA;    # for plant rated in apparent power
    reference = "Mersen T-link data sheet, table 2";
}
----

The three ratings are independent and none of them is read as a curve:
they are what the equipment is *called*, printed in the legend so a
reader can check the device on the sheet against the one in the
schedule. `rating_S` is the natural one for a transformer, whose damage
curve is a `transformer_damage` device.

`reference` records where a published table came from. A number nobody
can trace is a number nobody can check, and a damage curve transcribed
from a data sheet three revisions ago is the kind of thing that
survives unnoticed for years. Sample 14 carries one on every device.

=== grade

[source,tc]
----
grade {
    primary       = R_FDR:51;      # must clear first
    backup        = R_INC:51;
    fault         = "F_lv_max";    # or scenario = "..."
    margin        = 0.30 s;          # constraint: minimum acceptable
    margin_target = 0.35 s;          # target: exact design margin
    tolerance_pct = 5;
    upstream      = true;          # also sweep above the declared fault
    upstream_to   = 20 kA;         # ceiling for that sweep
    comment       = "feeder against incomer";
}
----

`margin` is a floor to satisfy; `margin_target` is a value to hit. Each
side is evaluated at the current *it* sees: a fault on one side of a
transformer is referred to the other by the turns ratio, per relay.

The upstream sweep runs by default: grading that holds at the declared
fault can still fail further up, where two characteristics converge.
Its ceiling is the largest fault at the primary's own level; a pair
that cannot reach it -- a spur fuse -- wants `upstream_to` or
`upstream = false`.

==== Letting the tool choose a setting

[source,tc]
----
grade {
    primary = R_FDR:51;
    backup  = R_INC:51;
    fault   = "F_lv_max";
    margin_target = 0.35 s;
    solve { strategy = "tight"; free = [tms]; }
}
----

`tight` takes the smallest `tms` meeting the margin; `loose` rounds up
to the next standard step; `safety_factor` aims past the target by a
margin of its own, for a study that has to survive settings drifting
before the next review. The solved value is marked `(auto)` in the
legend.

`solve` *applies* the setting it computes. The curve is drawn at the
solved dial, the margins are computed from it, and that is the setting
the study asserts -- what is drawn is what is used.

A dial already in the file is superseded rather than discarded. The
legend says `TMS 0.175 (auto, was 0.45)` and the report carries a
`SOLVE_OVERRODE_SETTING` warning naming both, because otherwise the
drawing and the settings sheet disagree with nothing saying which
governs -- and a commissioning engineer sets from the drawing.

*One relay has one dial.* An incomer backing two feeders, or one backup
graded under two conditions, is the ordinary case -- and both grades
want a say in the same setting. Which wins is not the order they are
written in: operate time rises with `tms` at every current and a margin
is a floor, so the *largest* `tms` any constraint asks for satisfies
every other. That one is applied; the rest report `SOLVE_SUPERSEDED`
naming the constraint that governed and the value it set:

----
[warning] SOLVE_SUPERSEDED: this solve asked for tms 1.050 on R_SRC:51;
the governing constraint is R_FDR_A:51 / R_SRC:51 at BOTH_CIRCUITS_IN,
which needs 1.350.
----

Every grade is then reported against the dial that was applied --
including grades that solve nothing, and including the case where the
solved element is another grade's *primary*. So a `solve` that breaks a
margin reported further up the file shows as a failure rather than as
two contradictory passes.

A grade naming a `scenario` solves exactly as one naming a `fault`, and
uses that scenario's `sees ... share` for the backup, being the current
the relay actually carries.

=== combine

A synthetic curve from several sources:

[source,tc]
----
combine {
    name    = "Bus OR";
    sources = [R_FDR_1:51, R_FDR_2:51];
    as      = envelope_min;        # fastest at each current
    style   = dashed;
}
----

`as` is `envelope_min`, `envelope_max`, `sum`, or `select_first`.

*Sources on two levels need `voltage`.* A combined curve is read at one
current, and across a transformer one current is two -- so a combine
spanning a transformer must say which bus it is stated at:

[source,tc]
----
combine {
    name    = "Board and upstream recloser";
    sources = [R_BOARD:51, recloser_R1];   # 400 V and 11 kV
    as      = envelope_min;
    voltage = LV;                          # read at the 400 V board
}
----

Each source is then asked about the amps its own winding carries: at
21 kA on the 400 V board the 11 kV recloser sees 763 A, and answers for
that. Feeding it the board's 21 kA instead asks it about a fault 27.5
times the one that happened, and the envelope claims a clearance that
does not exist -- which is why leaving `voltage` out here is an error
rather than a default. Sources that all sit on one level take it from
them and need say nothing.

[NOTE]
====
A mark is drawn only where the sheet can show it. Zoom in -- or declare
narrow `view { current_min / current_max }` bounds -- and anything whose
anchor falls outside the window is left off rather than drawn beyond the
frame: a marked point moves to the legend list, and annotations are
counted in the notes.

They are suppressed rather than pinned to the edge, because a mark on
the frame claims a current it does not have, which is a worse answer
than an absent mark the legend still accounts for.
====

=== group

A protection chain: the relays in series on one path, upstream first.

[source,tc]
----
group FEEDER_1 { members = [R_INCOMER, R_FDR_1, R_RMU_1]; }
----

A view names a group with `group = FEEDER_1;` and draws exactly those
relays' elements, instead of every element listing every sheet it
belongs on. `name` and `description` are the same two tiers every
other block takes.

A group holds *relays*, not marks. `times`, `point` and `annotate` are
scoped by `view` / `views`, the same as every other mark -- a group
selects which relays a sheet draws, not which requirements or
observations belong on it, and a mark that matters to one chain's sheet
names that sheet directly.

Ordered because the order is what a grading pair reads: upstream first
is what makes "the relay after this one in its group" a real question
once a study grades a whole chain rather than one pair at a time.

=== point and annotate

Marked coordinates and callouts. These are how a study *argues* --
inrush the curve must sit above, a withstand limit it must sit below,
a margin the reader should not have to measure:

[source,tc]
----
point "TX1_inrush" {
    I       = 5250 A;
    t       = 0.10 s;
    voltage = "HV";
    label   = "TX1 inrush\n12 x FLC, 100 ms";   # \n breaks the line
    shape   = "cross";
    coords  = true;                # append "(5.25 kA, 100 ms)"
}

annotate {                          # margin between two curves
    primary = R_FDR:51;
    backup  = R_INC:51;
    fault   = "F_lv_max";
    label   = "CTI";
}

annotate {                          # a single curve at one current
    on_curve = R_INC:51;
    at_I     = 18.4 kA;
    style    = leader;              # leader | pin | tag
    label    = "HV max fault";
}
----

==== A point declares its current as a fault does

One vocabulary for every current in the language. `I` is phase
current, `I2` negative sequence, `I0` the zero-sequence component,
`residual` the residual `3*I0` -- the same keys a `fault` and a
`scenario` level use. The sheet then takes whichever component its axis
is drawn in:

[source,tc]
----
point "ext fault I2" { I2   = 49 A;  t   = 0.10 s; voltage = "HV"; }
point "TX inrush"    { I    = 212 A; t   = 0.12 s; voltage = "HV"; }
point "2ph min"      { I    = 390 A; type = two_phase; t   = 0.2 s; }
----

`type` supplies the ratios, so the last of those is placed on an `I2`
sheet at `390/sqrt(3)` without anything else being declared.

A marker whose component the sheet is not drawn in is left off and named
in the legend, with the key that would fix it. Nothing changes for a
point declaring `I` on a phase axis -- which is the default -- so
existing studies are untouched.

==== Saying where, when the axis is not phase current

An annotation's current is declared the way a fault, a scenario level
and a point declare theirs, because the abscissa is not always phase
current:

[source,tc]
----
annotate { primary = R_850:46; backup = R_SEL:46; at_I2   = 225 A; }
annotate { primary = R_850:46; backup = R_SEL:46; at_I   = 390 A; type = two_phase; }
----

Both put the arrow in the same place on an `I2` sheet: the first names
the component, the second gives the phase current and lets the type
derive it. `at_I` still means phase current, so nothing written
before this moves.

Every component has a spelling: `at_I` for phase, `at_I1`, `at_I2`,
`at_I0`, and `at_residual` for `3*I0` -- or `at_3I0`, an alias for the
same figure spelled the way `quantity` itself names the axis. There is
also `at_t`, which places the mark by *time* rather than current -- for
reading a curve the other way round, "what current gives me 300 ms?".

[source,tc]
----
annotate { on_curve = R_TEE:51G; at_residual = 2.4 kA; label = "51G"; }
annotate { on_curve = R_RING:51P; at_I1      = 800 A;  label = "I1"; }
annotate { on_curve = R_RING:51G; at_I0      = 800 A;  label = "I0 not 3I0"; }
annotate { on_curve = R_TEE:51;  at_t        = 300 ms; label = "at 300 ms"; }
----

Sample 17 draws all of them across four sheets of one study.

The component you write has to be one the annotated element measures.
Scalings of the same component convert -- `at_I0` on a `3I0` element is
multiplied by three -- but *different* components do not substitute for
each other, so `at_I1` beside an element scaled in `3I2` is
`ANNOTATE_QUANTITY_MISMATCH`. An annotation naming a curve must also
say where on it to sit: a current, a time or a condition, or else
`ANNOTATE_NO_POSITION`. And `style = pin` draws a marker only, so a
`label` beside one is `ANNOTATE_LABEL_NOT_DRAWN` -- use `leader` or
`tag` for text.

Where a mark cannot be placed for reasons that depend on the sheet --
a curve that never reaches the time asked for, a pair that does not
operate at the current given, a mark past the `I_cutoff` of the curve
it marks -- it is dropped rather than left floating, and the sheet
names it in its notes. That is distinct from the *count* of
annotations outside the plotted range, which changes as you zoom.

`voltage` names the level the figure is read at, defaulting to the
view's. Without it a bare current was taken in *each* referenced
element's own frame, so one number meant two different currents across
a transformer and the drawn margin contradicted the report.

A condition and a bare current are alternatives; declaring both is an
error rather than a rule about which wins.

==== Pointing at one stage

A reference means the element as a whole -- the composite, which is
what the relay trips at. Add a stage to mean just that stage:

[source,tc]
----
annotate { primary = R_850:46/energ; backup = R_SEL:46; at_I2   = 225 A; }
----

which is what a study whose stages are alternatives under different
conditions needs: one inrush-blocked, one not, and the margin that
matters is to the one that is armed.

The far end need not be a curve. A marked `point` asserts a coordinate
the study is sure of -- an inrush peak, a withstand corner, a figure
off a data sheet -- and the gap between a characteristic and one of
those is as much a margin as the gap between two relays:

[source,tc]
----
annotate { primary = R_INC:51; point = "Inrush"; label = "above inrush"; }
----

The point supplies both the current the arrow stands at and the time
of its far end, so no `at_I` and no condition are needed. Add an
`at_t` and it becomes a *current* margin instead, with the point as
the far end of a horizontal span.

Where an element's stages are drawn separately
(`view { stages = "individual" }`), a margin to the element as a whole
measures the *closest* pair of stages, that being the binding gap. Where
the sheet draws the composite there is only one line per element, so the
margin is to that -- otherwise the arrow would end in mid-air.

==== Margins: in time, and in current

The vertical arrow measures a *time* margin between two curves at one
current. Its horizontal counterpart measures a *current* margin at one
time, reported as a percentage -- which is how a current-grading margin
is quoted, amps meaning little without knowing where on the axis you
are:

[source,tc]
----
annotate {                          # curve to curve
    primary = R_FDR:51;
    backup  = R_INC:51;
    at_t    = 1 s;
    label   = "Current margin";
}

annotate {                          # curve to a fault level
    primary = R_RMU:50;
    at_t    = 20 ms;
    fault   = "2ph min";
    label   = "min 2ph";            # -> "min 2ph 152.9%"
}

annotate {                          # curve to a marked point
    primary = R_RMU:50;
    at_t    = 20 ms;
    point   = "TX inrush";
    label   = "inrush";             # -> "inrush 120.3%"
}
----

`at_t` is what makes it a current margin. The far end is another
characteristic (`backup`), a declared condition (`fault` / `scenario`),
or a marked point (`point`) -- a pickup is as often quoted against a
fault level or an inrush peak as against another relay. Both ends are
put on the sheet's own axis before they are compared, so the figure is
the one the drawn arrow spans.

The percentage is *the larger current over the smaller*, unsigned, and
nothing else. A 255 A pickup against a 390 A fault reads `152.9%`; the
same pickup against a 212 A inrush reads `120.3%`. Never below 100%,
and identical whichever end you declare as the `primary`.

Which way round it runs is left to the arrow and the legend, both of
which are already on the sheet saying it.

NOTE: Used to be signed against the primary, so one gap read as two
different magnitudes depending on which end you wrote first.

A current is read as *the smallest current whose operate time is at or
below* `at_t`. On an inverse curve that is the point where it crosses;
on a definite-time stage, which is flat, it is the pickup -- which is
the answer meant.

==== A dimension with no curve at either end

Both margin forms measure between two *characteristics*. A required
grading band, the window a setting has to fall inside, a range a
supplier quotes -- none of those is a curve, so `from` and `to` draw
the dimension directly:

[source,tc]
----
annotate { from = 500 ms; to = 800 ms; at_I = 6 kA;  label = "band"; }
annotate { from = 1.2 kA; to = 3.2 kA; at_t = 4 s;   label = "window"; }
annotate { from = 840 A;  to = F1;     at_t = 8 s;   label = "reach"; }
----

The *unit* decides which way it runs: two times draw a vertical span
(`at_I` or a condition), two currents a horizontal one (`at_t`) -- and
either currents end may name a condition instead, as line three does.

A vertical span is labelled with the elapsed time, a horizontal one
with the larger over the smaller, exactly as a current margin is. Both
read the same written either way round.

==== Taking the current from a condition

Neither block needs the current typed in. Name a declared condition --
a `fault` or a `scenario` -- and the figure comes from the study, at the
quantity the sheet is drawn against, in the frame of whatever the mark
belongs to:

[source,tc]
----
point "ACB clears" {
    scenario = "system normal";      # instead of I
    voltage  = "HV";
    t        = 2.00 s;
}

annotate {
    primary   = R_850:46;
    backup    = R_FDR:46;
    scenarios = ["system normal", "one tx out"];   # one margin each
    label     = "CTI";
}
----

`fault`, `faults`, `scenario` and `scenarios` are all the same key: a
condition, one name or a bracketed list of them. Name several and the
mark is drawn once per condition, each at its own current -- which is
how a margin is shown at both a maximum and a minimum fault on one
sheet. A point drawn several times has the condition appended to its
label, so the markers can be told apart.

For a margin, each side is read in *its own* frame, exactly as grading
does, so the figure drawn is the one the report computes. A scenario
that declares both levels is not referred at all.

A point states its current *or* names a condition -- doing both is an
error rather than a precedence rule to remember. Naming a scenario that
declares nothing at the point's level is an error too: the mark asks for
a position that was never measured.

A condition may name its level: `scenario = "S".LV;`.

==== Which current the sheet is drawn against

By default the axis is simply *current*, and every curve is drawn
against it whatever that curve measures:

[source,tc]
----
view { voltage = "HV"; }                 # quantity = any, the default
----

That is the case where you want several characteristics on one sheet
without arguing about components. The legend states each curve's
measured quantity, which is what keeps a mixed sheet readable.

Naming a quantity opts into a stricter sheet:

[source,tc]
----
view { voltage = "HV"; quantity = I2; }  # or 3I0, I0, I1, 3I2, phase, any
----

Then only elements measuring that quantity are drawn, the rest are
counted in the legend, and each fault rule stands at the fault's value
of that component. The axis title names it, so the units are never a
guess: `Current (A primary · I2 · HV · 33 kV)`.

===== Fault types, and mixing quantities on one sheet

At a single fault the phase current and the sequence components are not
independent -- they are fixed multiples of one another, decided by what
kind of fault it is. Declare the type and the tool knows the ratios:

[source,tc]
----
faults {
    "F_2ph" { I   = 390 A; type = two_phase; voltage = "HV"; }
}
----

Types are `three_phase`, `two_phase`, `two_phase_earth`,
`single_phase_earth`. Against the condition's *own* declared phase
current, and with `Z1 = Z2`:

[cols="1,1,1,1,1", options="header"]
|===
| Type | `I1` | `I2` | `I0` | residual `3I0`

| `three_phase` | `I` | 0 | 0 | 0
| `two_phase` | `I/√3` | `I/√3` | 0 | 0
| `single_phase_earth` | `I/3` | `I/3` | `I/3` | `I`
| `two_phase_earth` | -- | -- | -- | --
|===

`two_phase_earth` derives nothing: its split between the sequence
networks depends on `Z0`, which the language does not carry, so declare
its components.

A declared component always wins over a derived one -- writing
`I2_A = 225 A` is how you override the table, and it sets the display
ratio as well as the graded value.

Naming the condition a sheet depicts unlocks two things:

[source,tc]
----
view { voltage = "HV"; quantity = I2; condition = "F_2ph"; }
----

* **Curves convert onto the axis.** A phase element is drawn at
  `I_phase = √3 × I2` for a phase-phase fault, so phase and
  negative-sequence characteristics can be read together. On a log axis
  a conversion is a constant shift, so operate times are untouched --
  only the abscissa moves. Each converted curve is named in the legend
  with the multiplier that placed it -- `R:51: phase drawn on the I2
  axis, x0.577` -- because its position rests on the depicted
  condition's ratios rather than on its own setting, and the multiplier
  is what makes that checkable against the axis.
* **Elements the condition cannot operate are suppressed.** On a
  `three_phase` condition there is no `I2` and no `I0`, so earth-fault
  and negative-sequence elements are left off rather than drawn where
  they could never operate. So is an element whose current cannot reach
  the sheet's level at all -- an HV residual element behind a delta is
  off *every* sheet of an LV earth fault, not only the residual one.
  Each is named in the legend with its reason:
+
[none]
* `... 51G measures residual 3I0, which does not cross HV to LV`
* `... 51G carries no residual 3I0 at HV under LV earth fault`

`condition` takes a scenario as readily as a fault. With a scenario the
ratios come from *the level the sheet is drawn in* -- never from another
level's figures, which would mix two turns ratios into one number:

[source,tc]
----
view { voltage = "HV"; quantity = I2; condition = "LV earth fault"; }
----

===== The same component in another scaling

`3I2` is three times `I2`, and `3I0` three times `I0`, whatever the
fault is. Those need no condition: an element set in `I2` is drawn on a
`3I2` sheet at a third of its own current, and a residual element
belongs on an `I0` sheet. Only relating *different* components -- phase
to `I2`, `I2` to `3I0` -- needs a condition to supply the ratios, and
the legend says so by name when one is missing.

===== What is between two levels

The turns ratio refers a *balanced* fault correctly and nothing else.
A delta-star transition rotates the positive- and negative-sequence
components in opposite directions, so they recombine differently on
the far side: a phase-phase fault on the star side comes out 2:1:1 on
the delta lines, the largest being `2/sqrt(3)` -- 15.5% more than the
ratio gives. The backup carries that, operates faster on it, and the
margin is smaller than the ratio alone would report.

Which it is depends on the windings, not the voltages. Say what the
nameplate says:

[source,tc]
----
system {
    voltages { "HV" { V = 33 kV; } "LV" { V = 0.48 kV; } }

    transformer "HV" to "LV" {
        vector_group = "Dyn11";
    }
}
----

`Dyn11`, `YNd1`, `YNyn0`, `Dd0`, and the bare `Dy` / `Yd` are all read;
the clock number is optional, a magnitude not depending on it.

From it follow both answers. Across a delta-star, a star-side fault
carries at `1` (balanced), `2/sqrt(3)` (phase-phase) or `1/sqrt(3)`
(phase-earth, the delta having absorbed the zero sequence). Across a
like-for-like connection nothing is transposed and the ratio stands.

Where the windings do not settle it -- a two-phase-earth fault, which
needs `Z0`; an earth fault across two earthed stars, where the split is
set by the zero-sequence impedance network -- grading refuses with
`REFERRAL_NEEDS_CONNECTION` rather than quoting the ratio. Declare the
condition as a `scenario` with figures at each level and nothing has to
be carried across at all.

Zero-sequence continuity follows from the group: a delta blocks it.
`zero_sequence` remains for the cases the windings alone do not decide
-- an earthing transformer, a star-star with one neutral lifted -- and
wins where both are written:

[source,tc]
----
system {
    voltages { "HV" { V = 33 kV; } "LV" { V = 0.48 kV; } }
    zero_sequence { "HV" to "LV" = blocked; }   # or continuous
}
----

Undeclared, a residual figure will not be referred between levels and
the pair is reported rather than graded on a guess. Positive and
negative sequence always refer, scaling with the turns ratio.

NOTE: Fault *rules* come from the `faults` block. A `scenario` drives
grading but draws nothing yet, so a study using scenarios alone has no
rules on its plot; declare a `faults` entry for the condition you want
marked.

==== The legend follows the view

The legend describes what is on the sheet, not what the file declares.

* A fault outside the current `view` has no rule on the plot, so it has
  no legend entry either -- an entry maps a dash pattern to a name, and
  says nothing when that dash is nowhere to be seen. Zoom out and it
  comes back.
* A marked `point` that *is* on the plot is left out of the panel: its
  marker already carries its label, so an entry would repeat it.
  A point that falls outside the view is listed, because that is then
  the only place it appears.

Both rules exist to keep the panel for what needs explaining. A legend
too tall for its space sheds detail before it sheds entries.

==== Labels place themselves

You do not position labels. Each one is anchored to its point, curve or
arrow, and the renderer puts it beside that anchor -- right by
preference, then left, then above or below. When two anchors are close
enough that the labels would overprint, the later ones are moved clear,
and any label moved far enough that the connection is no longer obvious
gains a thin leader back to its anchor.

Labels never leave the plot, and placement is deterministic: the same
study always produces the same sheet, so a reissued drawing diffs
cleanly.

If a cluster still looks crowded, the fix is in the study rather than
the label: narrow the `view` so the anchors spread out, or move some of
the marked points to a second sheet.

=== view

What is on screen, not what is true:

[source,tc]
----
view {
    voltage     = "HV";            # frame every curve in the 33 kV side
    stages      = "individual";    # or "composite" (default)
    current_min = 100 A;
    current_max = 30 kA;
    time_min    = 20 ms;
    time_max    = 100 s;
    current_pad = 0.2;             # padding when bounds are automatic
}
----

Set the bounds explicitly if the automatic range is unhelpful --
auto-ranging can run wide and squash the curves.

==== Padding, a second axis, and secondary amps

Where fixed bounds are too rigid -- a study still being settled, whose
curves move as pick-ups change -- pad the fitted range instead. Each
value is a factor: `1.5` leaves half again as much room.

[source,tc]
----
view {
    voltage          = "HV";
    current_pad      = 1.5;    # both ends of the current axis
    current_pad_low  = 2;      # or one end at a time
    current_pad_high = 1.2;
    time_pad         = 1.5;
    time_pad_low     = 2;
    time_pad_high    = 2;

    second_axis      = "HV";   # a second current scale, in HV amps
    reference_ct     = R_FDR;  # the curve the axis is anchored to
}
----

===== A second scale, in another level's amps

`second_axis` names a voltage level and puts a second current scale
across the top, in that level's amps. Ampere-turns referral is a
*uniform* map -- every current scales by the same `V_view / V_second`
-- so it is the same pixels relabelled: exact, and no curve moves.

It is how a cross-level sheet is meant to be read. On sample 10's
33/11 kV cascade the incomer's 700 A pickup is 2.1 kA in the 11 kV
frame the sheet is drawn in; the top scale reads 700 A instead. Each
fault rule is captioned up there too, the HV figure belonging beside
the HV scale rather than bracketed onto a label at the other end of
the sheet.

Where `page { axes { mirror } }` would repeat the bottom scale along
the top, the second axis takes that strip; the mirrored *time* scale
on the right is unaffected. An undeclared level is an error; the
sheet's own level is a warning.

===== Anchoring the scale

`reference_ct` names the curve the axis is anchored to:
`axis = "secondary"` divides by that relay's CT ratio, so the numbers
match the settings sheet in front of the reader; `axis = "multiples"`
divides by that element's *pickup*, so the scale reads `0.5x`, `2x`,
`20x` as a relay manual states its curves.

One axis carries one scale, so `multiples` anchors to one curve rather
than -- as the spec used to claim -- each curve's own pickup: lining
them all up on `M = 1` would mean moving the curves. Every curve still
*computes* against its own; only the labelling uses the reference.
Omitted, the highest on the sheet is used.

`axis` itself takes `"primary"` (the default), `"secondary"`, or
`"multiples"`.

==== Keeping a mark to one sheet

`faults`, `times`, `point` and `annotate` all take a `view`, naming the
sheet or sheets they belong to. One name or a list:

[source,tc]
----
faults {
    "Board max"  { I = 9.4 kA; voltage = "MV"; }                    # every sheet
    "Earth max"  { I = 1.6 kA; voltage = "MV"; view  = "Earth"; }   # one sheet
    "Both ways"  { I = 3.1 kA; voltage = "MV"; views = ["Phase", "Earth"]; }
}

point "Inrush" { I = 2.4 kA; t = 100 ms; view = "Phase"; }

annotate { on_curve = R:46; at_I = 800 A; label = "I2 only"; view = "I2"; }
----

A study with a phase sheet and a sequence sheet carries marks that mean
something on one and nothing on the other.

An `element` takes it too, which keeps a whole *curve* to the sheets it
belongs on rather than only the marks around it:

[source,tc]
----
element 51P { function = "phase_oc"; measures = I1;
              curve = iec.si; I_pickup = 500 A; tms = 0.30;
              views = ["Phase", "Negative sequence"]; }
----

A curve kept off a sheet is left out of that sheet's axis fit, so it
cannot widen the scale for something not drawn; nor is it listed among
the curves the sheet could not place.

Leaving `view` off means every sheet. `~name` means every sheet but
that one; mixing `~` with a plain name is refused. Works in `fault`
lists too.

=== view -- one per sheet

A study may declare several views. Each is one sheet: a phase sheet and
a negative-sequence sheet of the same network, or the same grading under
two conditions. Name them, and each carries its own title:

[source,tc]
----
view "Phase grading" {
    voltage   = "HV";
    quantity  = phase;
    condition = "3ph min";
    title     = "Broadsound BESS RMU — phase grading";
}

view "I2 grading" {
    voltage   = "HV";
    quantity  = I2;
    condition = "1ph min";              # the scenario
    title     = "Broadsound BESS RMU — negative-sequence grading";
    subtitle  = "480 V earth fault seen at 33 kV";
}
----

The playground shows a picker beside the plot when a study declares more
than one. Nothing changes for a study with a single unnamed `view`.

Without the playground -- the CLI, or the API -- the sheet is chosen in
one of three ways, most specific first:

[source,bash]
----
tc-curves render study.ptc --svg -o out.svg --view "I2 grading"
----

[source,tc]
----
view "I2 grading" { default = true; ... }   # when nothing else says
----

and failing both, the first declared view. An unknown `--view` name is
an error listing the sheets the study does declare, rather than a
silent fall back to the first: the point of asking was to get a
particular sheet. From the API, pass the view itself:
`renderStudy(result, { view: result.study.views[1] })`.

`title` and `subtitle` on a view override `page { title }`, which every
sheet shares -- a negative-sequence sheet headed "Phase grading" because
the page said so is worse than no title. `page` keeps the paper and the
decoration; the view keeps what the sheet is *of*.

[NOTE]
====
Presentation stays in the presentation layer. A `scenario` is only what
the fault study measured, and stays readable as such; the *view* names
the condition it depicts. Putting a `view` inside a `scenario` would
have mixed the two and needed a precedence rule between the sheet's own
settings and the top-level ones -- and it could not express two sheets
of one condition, which is the common case.
====

=== page

Paper, decoration, and where the legend goes:

[source,tc]
----
page {
    size        = "A4";            # A0..A5, Letter, Legal, Tabloid
    orientation = "portrait";      # or landscape (default)
    margins_mm  = 4;               # all four sides; 0 = edge to edge
    stretch     = true;            # give the plot the unused band below the axis
    theme       = "light";
    border      = true;            # drawing frame + title block
    legend      = { style = "direct"; };
    axes        = { mirror = true; };       # repeat the scales top and right
    faults      = { width_px = 1.5; };
    title       = { text = "Northgate 11 kV"; subtitle = "Feeder grading"; };
}
----

==== Fitting a portrait sheet

Three levers, in the order they matter:

. `legend { style = ... }` -- a right-hand column costs about a third
  of a portrait sheet's width. `inside` floats the same panel over the
  plot; `direct` drops it and labels each curve in place; `none`
  removes identification entirely.
. `stretch = true` -- reclaims the fixed band reserved below the axis
  for stacked fault names.
. `margins_mm` -- `4` is a sensible print margin, `0` fills the sheet.

A legend too tall for its space sheds detail rather than running off
the page: make and model first, then settings, then names only, and
finally `+N more not shown`.

==== Every page option

All optional, all independent. Sample 16 sets every one of them in a
single sheet, which is the faster way to read them.

*Paper and theme*

[source,tc]
----
page {
    size        = "A3";        # A0..A5, Letter, Legal, Tabloid
    orientation = "landscape";
    theme       = "monochrome";   # light, dark, monochrome, print
    watermark   = "UNISSUED — FOR COMMENT";
    stretch     = false;
    border      = true;
    margins_mm  = { top = 14; right = 12; bottom = 16; left = 18; };
}
----

`theme` picks the ink set: `light` and `dark` for screens, `print` for
a mono plan copier, `monochrome` further still -- curves distinguished
by dash pattern alone. `watermark` prints diagonally across the plot,
for status. `margins_mm` takes one number for all four sides or a
block naming each, and is the *paper* margin used on export.

`size` takes a paper keyword or a sheet stated outright --
`size = { width_mm = 180; height_mm = 120; };` -- which is what a
figure sized to a report's text column wants and no keyword gives.
Both dimensions are required; one alone is `PAGE_SIZE_INCOMPLETE`,
not a guess at the other.

*Legend*

[source,tc]
----
page {
    legend = {
        show     = true;
        style    = "column";       # column, inside, direct, none
        position = "top_right";    # top_right, top_left, bottom_right,
                                   # bottom_left, right, left
        title    = "Protection";
        color    = "#222222";
        swatch   = "line";         # line, box, circle
        currents = "both";         # primary, secondary, both
        notes    = true;
    };
}
----

`swatch` is the mark beside each entry. `line` is the default and the
only one that can carry the curve's own dash pattern -- which is half
of how two curves are told apart once the palette runs out -- so
`box` and `circle` are right only where every curve has its own hue.

`currents` decides whether pick-ups are quoted in primary amps,
secondary amps, or both. A panel headed one way and figured the other
is off by the CT ratio, which is an error that ends up in a relay.

*Axes and grid*

[source,tc]
----
page {
    axes = {
        color         = "#333333";
        grid_color    = "#d8d8d8";
        label_color   = "#444444";
        label_size_px = 11;
        tick_size_px  = 9;
        frame         = true;
        mirror        = false;     # repeat the scales top and right
    };
    scale = {
        auto         = true;
        tick_density = "normal";   # sparse, normal, dense
    };
}
----

Keep the grid recessive: it is read *off*, not looked at. Major and
minor lines should differ (`grid_minor_style`) or finding a decade
means counting.

`scale` can also fix the window with `x_min`/`x_max`/`y_min`/`y_max`,
though `view { current_min ... }` is the usual place.

*Curves, points and leaders*

[source,tc]
----
page {
    curves = {
        palette       = "okabe_ito";   # default, okabe_ito, high_contrast,
                                       # grayscale, ieee, monochrome
        line_width_px = 1.8;
        auto_color    = true;
        nudge_px      = 3;             # separation drawn between curves
                                       # that coincide; 0 draws them on
                                       # top of one another
    };
    points = {
        color   = "#111111";
        shape   = "circle";       # circle, square, diamond, triangle, cross, x
        size_px = 9;
        outline = true;           # ring in the page colour, so a marker on a
                                  # curve reads as being in front of it
    };
    leaders = {
        show            = true;
        style           = "arrow";     # line, arrow, dot
        width_px        = 0.9;
        color           = "#666666";
        label_offset_px = 14;          # how far a moved label sits from its mark
    };
}
----

`nudge_px` is why two relays with the same setting read as two lines
rather than one. Coincident curves are separated perpendicular to the
line and symmetrically, so the pair's centre is where the
characteristic is, and only along the stretch where they are together.
It is deliberate error, so the notes declare it and name them --
`view { nudge_px }` overrides it per sheet. Nothing else moves: the
report comes from the model, and the pickup tick below the axis is
drawn from its own figure, so a sheet whose risers are 3 px apart
still states every pickup exactly.

`palette` is worth a moment. `default` is a general-purpose set;
`okabe_ito` is chosen to stay distinguishable under the common forms of
colour blindness; `high_contrast` is for a projector or a poor screen;
`ieee` follows the convention of the standards' own figures;
`grayscale` and `monochrome` are for print, the latter leaning on dash
patterns rather than lightness.

`auto_color` lets the tool assign hues in slot order. Turn it off and
every curve needs its own `color`.

*Title block and footer*

[source,tc]
----
page {
    title = {
        text         = "[meta.project] — [meta.study]";
        subtitle     = "Drawing [meta.drawing]";
        align        = "left";        # left, center, right
        color        = "#000000";
        font_size_px = 15;
    };
    footer = {
        left         = "[meta.drawing] rev [meta.revision]";
        center       = "[meta.engineer] · [meta.date]";
        right        = "Sheet [page] of [of]";
        font_size_px = 8;
        color        = "#555555";
        border       = true;
    };
}
----

Both expand macros: `[meta.<key>]` reads any key from the `meta` block
-- including ones you invented, since `meta` carries anything through
-- and `[date]` is today. `[page]` and `[of]` paginate a PDF export;
a single SVG has no pagination to report and prints `?`.

With `border = true` the footer is drawn along the foot of the title
block, beside the drawing's own fields rather than instead of them.

*Rules*

[source,tc]
----
page {
    faults = { style = "dashed"; color = "#c0392b"; width_px = 1.4; labels = true; };
    times  = { style = "solid";  color = "#1d7a4c"; width_px = 1.6; labels = true; };
}
----

Both take `solid`, `dashed` or `dotted`. They are drawn in different
inks by default, so it is never a question which axis a rule belongs
to. `labels = false` keeps the rule and drops its caption.

==== Notes, and getting the space back

The panel ends with a `Notes` block: what the sheet left out and why --
a curve the condition suppresses, a marker whose component this axis is
not drawn in, a scenario with nothing to say at this level. It sits at
the foot because the list of characteristics is what a reader wants
first; the caveats are what they come back for.

They give way before the settings as space runs short, saying how
many. Turning them off is the only silent way:

[source,tc]
----
page { legend = { notes = false; }; }
----

Above it, under its own `Comment` heading, goes whatever the office
put there on purpose -- the issue the settings were checked against,
an assumption the study rests on, who to ask. One string, or a list of
lines:

[source,tc]
----
page {
    legend = {
        comment = [
            "Settings checked against issue D of the fault study.",
            "Source impedance assumed 250 MVA at the 11 kV board.",
        ];
    };
}
----

The two are separate on purpose: `Notes` is the tool's account of what
it could not draw and changes as the study does; the comment is yours
and does not.

If the panel is still short of room, in the order that costs least:

. `legend { style = "inside" }` floats it over the plot, or
  `style = "direct"` drops it and labels each curve in place -- either
  returns about a third of the sheet's width.
. `page { stretch = true; }` reclaims the band reserved below the axis.
. `margins_mm = 4`, or `0` to fill the sheet.
. Split the study across two `view` blocks; each sheet then carries
  only the curves and notes that belong to it, which is usually the
  real fix when one panel is trying to explain two stories.

==== Settings in secondary amps

A study is written in primary amps because that is what the fault study
gives, but the number an engineer types into the relay is the secondary
one. `legend { currents }` asks for that figure, whatever the abscissa
is doing:

[source,tc]
----
page {
    legend = { currents = "secondary"; };   # or "both", or "primary"
}
----

* `primary` -- as declared. The default.
* `secondary` -- divided by the relay's `ct_ratio`: a 720 A pickup
  behind a 600/5 CT reads `6 A sec`.
* `both` -- `720 A (6 A sec)`.

Independent of `view { axis }`, which decides what the *current axis*
is: a sheet can have a primary-amp axis and settings-sheet figures
beside it, which is what a commissioning copy wants.

The conversion needs `ct_ratio` on the relay. An element without one
keeps its primary figure and is named in the legend -- a panel headed
one way and figured the other is out by the ratio, which is the sort of
error that reaches a relay.

== Reading the output

A margin report row per grading pair:

----
grade R_FDR:51 / R_INC:51:
    fault           = F_lv_max (I_f = 6400 A on LV)
    CTI_min         = 0.300 s
    seen by primary = 6400 A    seen by backup = 2133 A
    t_primary       = 0.274 s        (M = 13.33)
    t_backup        = 1.912 s        (M = 2.96)
    achieved margin = 1.639 s        -- pass
    overall         : PASS (worst 1.639 s at 6400 A)
----

`seen by backup` differs from `seen by primary` when a transformer sits
between them: ampere-turns balance, so the 33 kV winding carries
`6400 x 11/33 = 2133 A`. Each multiple is computed from the current in
that relay's own winding.

== Diagnostics you are most likely to meet

[cols="1,1,3", options="header"]
|===
| Code | Severity | Meaning

| `MEASURES_REQUIRED` | error | A `neg_seq` element does not say whether its pickup is `I2` or `3I2`.
| `SEQUENCE_DATA_MISSING` | error | An element measures a component the fault or scenario does not declare.
| `SEQUENCE_ACROSS_LEVELS` | error | A zero-sequence figure would have to cross a transformer. Declare it at the relay's own level.
| `CT_RATIO_MISSING` | error | A secondary-side pickup with no `ct_ratio` to convert it.
| `DUPLICATE_KEY` | error | A key assigned twice in one block.
| `MISSING_VALUE` | error | An `=` with no value after it.
| `MARGIN_BELOW_CTI` | error | A declared `margin_target` is below the `margin` floor.
| `ZERO_DELAY_NOT_PLOTTABLE` | warning | `t_delay = 0 s`, which has no log-axis position; drawn at 20 ms instead.
| `GRADE_MIXED_QUANTITY` | warning | The two sides of a grade measure different currents. Legitimate, but stated.
| `RELAY_VOLTAGE_UNSPECIFIED` | warning | A relay has no `voltage` in a study with several levels.
| `FAULT_SINGLE_POINT` | info | Only `I` given, so `I_min` and `I_max` default to it.
|===

== Writing a study from scratch

A checklist, in the order that avoids rework:

. **Levels first.** `system { voltages { ... } }`. Every relay and
  fault refers to a level by name.
. **Fault data next**, from the network study. Use `faults` for phase
  currents; use `scenario` if any element measures a sequence
  component, and declare each level explicitly.
. **One relay per protected item**, with `ct_ratio` if any pickup is in
  secondary amps.
. **Elements in device-number order**, each with `function`. Add
  `measures` to every `neg_seq` element. Give instantaneous stages a
  real operate time, not zero.
. **Grade downstream against upstream**: `primary` is the element that
  must clear first. The sweep above the fault runs by default.
. **`view` and `page` last** -- they change presentation only. Bound
  the current axis explicitly.
. Run `check`, then `report`, then render and *look at the plot*.
  Curves that vanish, labels that collide, and margins in the wrong
  direction are all obvious in the picture and invisible in the source.

=== Common mistakes

* Omitting units. No key names its own unit, so the unit is always
  yours to write: `I_pickup = 480 A`, `V = 33 kV`, `margin = 0.3 s`.
  A suffix is checked against the quantity the field takes, so
  `I_pickup = 5 ms` is refused as well as `I_pickup = 4 KA`.
* Using `t_delay = 0 s` for an instantaneous element. It will not
  appear on the plot.
* Grading with `primary` and `backup` the wrong way round. The primary
  is downstream and must be *faster*. A negative margin usually means
  they are swapped.
* Referring a residual current across a transformer. Declare it at each
  level with a `scenario`.
* Assuming the study's largest fault is visible to a sub-feeder deep in
  a cascade. The sweep bounds by voltage, not position: use
  `upstream_to`.
* Expecting the tool to compute fault levels. It does not; they are
  input.
