A practical guide to writing `.tc` files: protection-relay time-current
grading studies as plain text.

This document is self-contained and example-led. It is the reference to
read (or to give a language model) when *authoring* a study. The
normative specification -- grammar productions, curve constant tables,
conformance requirements -- is a separate document, `spec/spec.adoc`;
where the two differ, the spec wins.

toc::[]

== Before anything else

A `.tc` file declares four things and asks one question:

. the *voltage levels* in the study,
. the *fault currents* (or scenarios) the study is judged against,
. the *relays* and their protection elements,
. the *grading pairs* -- which element must clear before which other.

The tool then computes each element's time-current characteristic,
checks every pair's coordination time interval (CTI), and draws the
log-log plot.

It does not compute fault levels. Short-circuit currents are input
data, taken from your network study.

=== A complete file

Every construct below is optional except `relay` and `element`. This is
a working study:

[source,tc]
----
meta {
    project   = "Riverside 33/11 kV";
    engineer  = "A. Cooper";
    date      = "2026-07-30";
    CTI_min_s = 0.30;              # default grading interval
}

system {
    voltages {
        "HV" { kV = 33.0; }
        "LV" { kV = 11.0; }
    }
    frequency_Hz = 50;
}

faults {
    "F_lv_max" { I_A = 6400 A;  voltage = "LV"; }
    "F_hv_max" { I_A = 18400 A; voltage = "HV"; }
}

relay R_FDR {
    name     = "Feeder 4";         # free text for the drawing
    voltage  = "LV";
    ct_ratio = 600/5;

    element 51 {
        function = "phase_oc";
        curve    = iec.si;         # IEC standard inverse
        I_pu     = 480 A;
        tms      = 0.30;
    }
}

relay R_INC {
    voltage  = "HV";
    ct_ratio = 600/5;

    element 51 {
        function = "phase_oc";
        curve    = iec.si;
        I_pu     = 720 A;
        tms      = 0.175;
    }
}

grade {
    primary   = R_FDR:51;          # must clear first
    backup    = R_INC:51;
    fault     = "F_lv_max";
    CTI_min_s = 0.30;
}

view { voltage = "HV"; }           # draw everything in the 33 kV frame
----

=== Running it

[source,bash]
----
tc-curves check  study.tc              # parse + validate only
tc-curves report study.tc              # margin report to stdout
tc-curves render study.tc --svg -o study.svg
tc-curves render study.tc --png -o study.png --width 1600
tc-curves render study.tc --pdf -o study.pdf
----

== Syntax essentials

* Blocks are `keyword { ... }`; statements inside end with `;`.
* Comments: `#`, `//`, and `/* ... */`.
* Strings are double-quoted. Escapes: `\"`, `\\`, `\n`, `\t`,
  `\u{XXXX}`. A `\n` inside a *label* breaks the line on the drawing.
* Numbers take a `_` group separator: `18_430` is `18430`.
* **Units are required** wherever the field is not unit-free. A bare
  number in a unit-bearing field is a parse error.

=== Units

[cols="1,3", options="header"]
|===
| Quantity | Suffixes

| Current | `A`, `kA`, `mA`
| Pickup, extra forms | `A_sec` (secondary amps, multiplied by `ct_ratio`), `A_pri` (primary, explicitly), `pu`, `xCT`, `xIn`
| Time | `s`, `ms`, `min`
| Voltage | `kV`, `V`, `MV`
| Power | `MVA`, `kVA`, `MW`
| Angle | `deg`
|===

`A_sec` is how a settings sheet reads. These are the same element:

[source,tc]
----
element 51 { I_pu = 5.0 A_sec; }         # x ct_ratio -> 600 A primary
element 51 { I_pu = 600 A; }             # same, stated as primary
element 51 { I_pu = 5.0 A; I_units = "secondary"; }   # older spelling
----

`A_pri` exists so one primary figure can sit inside an element
otherwise dialled in secondary amps.

=== Two errors worth knowing

`DUPLICATE_KEY`:: A key assigned twice in one block. The later value
used to win silently.

`MISSING_VALUE`:: An `=` with nothing after it.

== Identifiers

*Relay ids* are letters, digits, underscores, starting with a letter or
underscore: `R_FDR_1`, `R_INC`.

*Element ids* are IEEE C37.2 device numbers and may start with a digit
and carry a letter suffix: `51`, `50`, `51G`, `67N`, `51X`, `87T`.

*References* are `relay:element` -- `R_FDR_1:51`, `R_850:51G`.

*Curve ids* are lower-case and namespaced: `iec.si`, `ansi.mi`.

`name` is separate from the identifier. The id is what references
resolve against; `name` is free text shown on the drawing, so renaming
for a reader never breaks a reference:

[source,tc]
----
relay R_INC {
    name = "Incomer 11 kV, panel 3";
    element 51 { name = "Phase OC (main)"; ... }
}
grade { backup = R_INC:51; }        # still the identifier
----

== Blocks

=== meta

Project identification. Open-ended; these keys are read by the title
block and the `[meta.*]` footer macros:

[source,tc]
----
meta {
    project   = "Northgate 11 kV";
    study     = "Feeder grading";
    engineer  = "A. Cooper";
    date      = "2026-07-30";
    revision  = "B";
    reference = "DOC-1234";
    CTI_min_s = 0.30;          # default for grade blocks that omit it
}
----

=== system

[source,tc]
----
system {
    voltages {
        "HV" { kV = 33.0; description = "33 kV switchboard"; }
        "LV" { kV = 11.0; }
    }
    frequency_Hz = 50;
    base_MVA     = 25;
    grounding    = "low_impedance";
    I_units      = "primary";      # study-wide default for pickups
}
----

Voltage levels are named, and the processor derives turns ratios from
them. There is deliberately no transformer block.

=== faults

One current at one level:

[source,tc]
----
faults {
    "F_lv_max" {
        I_A         = 6400 A;
        min_A       = 4000 A;      # sweep the CTI check across a range
        max_A       = 8000 A;
        voltage     = "LV";
        description = "Busbar 3ph, system normal";
    }
    "F_lv_earth" {
        I_A     = 6400 A;
        I0_A    = 800 A;           # zero-sequence component
        I2_A    = 800 A;           # negative-sequence component
        earth_A = 2400 A;          # residual 3*I0, if you prefer
        voltage = "LV";
    }
}
----

`I_A` is the *phase* current. `I0_A` is the component `I0`; `earth_A`
is the residual `3*I0` stated directly. Declare either -- the processor
derives the other, and errors if you declare both inconsistently.

If only `I_A` is given, `min_A` and `max_A` default to it.

=== times

Required clearances, drawn as horizontal rules -- the other axis's
answer to a `fault`:

[source,tc]
----
times {
    "Arc flash limit"     { t_s = 200 ms; description = "PPE category boundary"; }
    "Grid code clearance" { t_s = 430 ms; }
    "Bus zone backup"     { t_s = 2 s; }
}
----

A study is judged against currents *and* against times: an arc-flash
limit, a transformer withstand, a grid-code disconnection time, a
bus-zone backup. Writing them down puts the requirement on the sheet
beside the characteristic that has to meet it, instead of the reader
holding the number in their head.

A time needs no voltage level -- a second is a second on every winding
-- which is the one way this is simpler than a fault. Each rule is
labelled on the plot, listed in a *Required times* legend section, and
widens the time axis so a requirement can never fall off the sheet that
is meant to show it being met. One declared outside an explicit
`view { time_min / time_max }` says so rather than disappearing.

Style them with `page { times = { color = ...; width_px = ...; style =
"solid" | "dashed" | "dotted"; labels = false; }; }`, which mirrors
`page { faults }`. They are drawn in a different ink from the fault
rules by default, so it is never a question which axis a rule belongs
to.

=== relay and element

[source,tc]
----
relay R_FDR {
    name      = "Feeder 4 (Mill Road)";
    maker     = "Schneider";
    model     = "MiCOM_P122";
    voltage   = "LV";
    ct_ratio  = 400/5;             # -> n_CT = 80
    direction = "forward";

    element 51 {
        name     = "Phase OC";
        function = "phase_oc";
        curve    = iec.si;
        I_pu     = 320 A;
        tms      = 0.12;
        reset    = "instant";
    }

    element 50 {
        curve   = definite;
        I_pu    = 9 kA;
        t_delay = 60 ms;           # not 0 -- see the warning below
    }
}
----

WARNING: `t_delay = 0 s` cannot be drawn. The time axis is logarithmic
and has no position for zero, so the stage is omitted from the plot
*and* the legend. Enter the relay's real operate time -- typically
10-40 ms for an instantaneous stage. The diagnostic is
`ZERO_DELAY_NOT_PLOTTABLE`.

==== Multi-stage elements

When one protection function has several stages, the plotted curve is
the pointwise minimum -- what the relay actually does:

[source,tc]
----
element 50 {
    function = "phase_oc";
    stages {
        stage main  { curve = definite; I_pu = 147 A; t_delay = 40 ms; }
        stage energ { curve = definite; I_pu = 255 A; t_delay = 20 ms; }
    }
}
----

Stage fields fall back to the element, so a pickup declared once on the
element applies to every stage that does not restate it.

=== Curves

Standard families, by namespace:

[cols="1,4", options="header"]
|===
| Namespace | Curve ids

| `iec` | `iec.si`, `iec.vi`, `iec.ei`, `iec.lti`, `iec.sti`
| `ansi` | `ansi.mi`, `ansi.vi`, `ansi.ei`
| `sel` | `sel.c1`..`sel.c5`, `sel.u1`..`sel.u5`
| `ge` | `ge.ur.si`, `ge.ur.mi`, `ge.ur.vi`, `ge.ur.ei`
| `abb` | `abb.ri`, `abb.rd`
| `siemens` | `siemens.inv`, `siemens.long_inv`, `siemens.long_vi`, `siemens.long_ei`
| `schneider` | `schneider.sit`, `schneider.vit`, `schneider.eit`
|===

Plus three non-catalogue forms:

[source,tc]
----
element 51 { curve = definite; I_pu = 3 kA; t_delay = 100 ms; }

element 51 {                                    # your own constants
    formula = { k = 4.0; c = 0.10; alpha = 0.50; };
    I_pu = 500 A; tms = 0.2;
}

element 51 {                                    # a published point table
    flex_points = [(240 A, 50.0 s), (600 A, 5.0 s),
                   (1200 A, 1.0 s), (5000 A, 0.20 s)];
    I_pu = 240 A; tms = 1.0;
}
----

`flex_points` are absolute amps and seconds; `tms` scales the times
linearly. Use them for anything the catalogue does not cover -- ACB
trip units, thermal curves, manufacturer data.

=== What an element measures

A relay does not measure "the fault current". Which current the pickup
refers to decides the multiple, and so the operate time:

[cols="1,2,2", options="header"]
|===
| `function` | Measures | Default

| `phase_oc` | phase current | `phase`
| `earth_fault` | residual `3*I0` | `3I0`
| `neg_seq` | negative sequence | *none -- you must state it*
| `thermal` | RMS phase current | `phase`
| `breaker_fail` | phase current | `phase`
|===

Override with `measures`, whose values are `phase`, `I1`, `I2`, `3I2`,
`I0`, `3I0`:

[source,tc]
----
element 51G { function = "earth_fault"; }                  # 3I0 by default
element 51G { function = "earth_fault"; measures = "I0"; }  # this IED is in I0
element 46  { function = "neg_seq"; measures = "I2"; }      # required
----

IMPORTANT: `neg_seq` has no default because IEDs differ over whether
the pickup is scaled in `I2` or `3*I2`. A factor of three is the
difference between an element that operates and one that does not, so
guessing is not acceptable. Omitting `measures` is the error
`MEASURES_REQUIRED`.

If an element measures a component the referenced fault does not
declare, that is the error `SEQUENCE_DATA_MISSING` and the pair is not
graded. No other quantity is substituted -- a margin computed off the
wrong current is a wrong number that looks right.

=== scenario

A `fault` is one current at one level. Referring it to another level by
the turns ratio is correct for phase current, and for positive and
negative sequence -- but **zero sequence does not cross a delta
winding**. No ratio carries it.

A `scenario` declares one condition at every level it is measured, so
nothing has to be transformed:

[source,tc]
----
scenario "LV earth fault" {
    description = "Single phase to earth at 0.48 kV";

    # star side: the components are equal for a phase-earth fault
    level "LV" { I_A = 460 A; I1_A = 153 A; I2_A = 153 A; I0_A = 153 A; }

    # delta side: no zero sequence gets through
    level "HV" { I_A = 3.9 A; I1_A = 2.2 A; I2_A = 2.2 A;  I0_A = 0 A;  }

    sees R_FDR { current_pct = 50; }   # parallel paths: half the current
}

grade {
    primary   = R_ACB:51;
    backup    = R_850:46;              # I2 backup
    scenario  = "LV earth fault";
    CTI_min_s = 0.30;
}
----

This is the reason an HV *negative-sequence* element, not an HV
residual element, backs up an LV earth fault: at HV the residual is
zero, so a `51G` there is blind to the fault. Declare it and the report
says so.

`fault` and `scenario` are alternatives; declaring both is an error.

==== Scenarios on the drawing

A scenario draws its own vertical rule, at **its own figure for the
level the sheet is in** -- 153 A of residual on an LV sheet, nothing at
all on a delta-side residual sheet. Nothing is referred across the
transformer, which is the whole reason to write one. The rule stands at
the value of whatever quantity the view is drawn against, so a sheet in
`I2` marks the scenario's `I2`.

Where a scenario cannot be marked, the legend says so rather than
leaving it off quietly -- grading still reports a margin against it, so
silence would invite the reader to assume it was not relevant:

[none]
* `system normal declares no currents at LV (has HV, MV)` -- it was
  never measured on the level being drawn. A scenario declaring just
  *one* level is unambiguous and is carried onto the sheet by the turns
  ratio instead.
* `system normal carries no residual 3I0 at HV` -- the component is
  zero there, which is a real answer and has no place on a log axis.

Faults and scenarios can share a sheet. When they do, the panel is
headed *Conditions* rather than *Faults*, and each scenario entry says
`scenario` under it, because the figure came from the study's own
measurement at that level rather than from a turns-ratio referral.

[WARNING]
====
A *curve* still crosses voltage levels by the turns ratio, because an
element's characteristic is a property of the element and not of any
condition. A scenario's per-level figures deliberately need not agree
with that ratio -- for the delta-star above, 460 A at LV is declared
against 3.9 A at HV, where the ratio alone would give 6.7 A.

So on a sheet drawn in one frame, a curve belonging to another frame is
positioned by kV, while the grading report for that pair uses the
scenario's declared figures. The margin in the report is the correct
one; the drawn curve can disagree with it. Keep a marked point on the
level and quantity the sheet is drawn in and it will sit where the
report says.
====

=== device

Fuses, cable damage curves, recloser characteristics -- anything with a
published characteristic that is not a relay element:

[source,tc]
----
device "spur_fuse_50T" {
    kind        = fuse;
    maker       = "Mersen";
    model       = "50T";
    rating_A    = 50 A;
    min_melt    = [(100 A, 100 s), (1 kA, 0.05 s)];
    total_clear = [(100 A, 200 s), (1 kA, 0.10 s)];
}
----

`kind` is one of `fuse`, `recloser`, `cable`, `transformer_damage`,
`motor_startup`, `breaker`. A fuse with both tables draws as a hatched
band. In grading it uses *total clear* as the primary and *minimum
melt* as the backup, which is the conservative reading each way.

Reference a device by its id, quoted or bare:
`grade { primary = "spur_fuse_50T"; }`.

Give it a `voltage` if the study spans more than one level. A published
fuse curve is in the amps of the winding it sits on, so without a level
its points are taken as already being in the view frame -- and on a
cross-voltage sheet the band is drawn out by the turns ratio. This is
not `rating_kV`, which is the fuse's own insulation rating:

[source,tc]
----
device "spur_fuse_50T" {
    kind      = fuse;
    voltage   = "LV";        # the level it sits on
    rating_kV = 12 kV;       # its insulation rating -- a different thing
    rating_A  = 50 A;
}
----

=== grade

[source,tc]
----
grade {
    primary       = R_FDR:51;      # must clear first
    backup        = R_INC:51;
    fault         = "F_lv_max";    # or scenario = "..."
    CTI_min_s     = 0.30;          # constraint: minimum acceptable
    margin_s      = 0.35;          # target: exact design margin
    tolerance_pct = 5;
    upstream      = true;          # also sweep above the declared fault
    upstream_to   = 20 kA;         # ceiling for that sweep
    comment       = "feeder against incomer";
}
----

`CTI_min_s` is a floor to satisfy; `margin_s` is a value to hit. Each
side is evaluated at the current *it* sees: a fault on one side of a
transformer is referred to the other by the turns ratio, per relay.

`upstream = true` is worth using. Grading that holds at the declared
fault can still fail further up, where two characteristics converge.
Bound it with `upstream_to` on a deep cascade -- the default ceiling is
the largest fault in the study, which a sub-feeder may never see.

==== Letting the tool choose a setting

[source,tc]
----
grade {
    primary = R_FDR:51;
    backup  = R_INC:51;
    fault   = "F_lv_max";
    margin_s = 0.35;
    solve { strategy = "tight"; free = [tms]; }
}
----

`tight` takes the smallest `tms` meeting the margin; `loose` rounds up
to the next standard step. The solved value is marked `(auto)` in the
legend.

=== combine

A synthetic curve from several sources:

[source,tc]
----
combine {
    name    = "Bus OR";
    sources = [R_FDR_1:51, R_FDR_2:51];
    as      = envelope_min;        # fastest at each current
    style   = dashed;
}
----

`as` is `envelope_min`, `envelope_max`, `sum`, or `select_first`.

=== point and annotate

Marked coordinates and callouts. These are how a study *argues* --
inrush the curve must sit above, a withstand limit it must sit below,
a margin the reader should not have to measure:

[source,tc]
----
point "TX1_inrush" {
    I_A     = 5250 A;
    t_s     = 0.10 s;
    voltage = "HV";
    label   = "TX1 inrush\n12 x FLC, 100 ms";   # \n breaks the line
    shape   = "cross";
    coords  = true;                # append "(5.25 kA, 100 ms)"
}

annotate {                          # margin between two curves
    primary = R_FDR:51;
    backup  = R_INC:51;
    fault   = "F_lv_max";
    label   = "CTI";
}

annotate {                          # a single curve at one current
    on_curve = R_INC:51;
    at_I_A   = 18.4 kA;
    style    = leader;              # leader | pin | tag
    label    = "HV max fault";
}
----

==== A point declares its current as a fault does

One vocabulary for every current in the language. `I_A` is phase
current, `I2_A` negative sequence, `I0_A` the zero-sequence component,
`earth_A` the residual `3*I0` -- the same keys a `fault` and a
`scenario` level use. The sheet then takes whichever component its axis
is drawn in:

[source,tc]
----
point "ext fault I2" { I2_A = 49 A;  t_s = 0.10 s; voltage = "HV"; }
point "TX inrush"    { I_A  = 212 A; t_s = 0.12 s; voltage = "HV"; }
point "2ph min"      { I_A  = 390 A; type = two_phase; t_s = 0.2 s; }
----

`type` supplies the ratios, so the last of those is placed on an `I2`
sheet at `390/sqrt(3)` without anything else being declared.

A marker whose component the sheet is not drawn in is left off and named
in the legend, with the key that would fix it. Nothing changes for a
point declaring `I_A` on a phase axis -- which is the default -- so
existing studies are untouched.

==== Saying where, when the axis is not phase current

An annotation's current is declared the way a fault, a scenario level
and a point declare theirs, because the abscissa is not always phase
current:

[source,tc]
----
annotate { primary = R_850:46; backup = R_SEL:46; at_I2_A = 225 A; }
annotate { primary = R_850:46; backup = R_SEL:46; at_I_A = 390 A; type = two_phase; }
----

Both put the arrow in the same place on an `I2` sheet: the first names
the component, the second gives the phase current and lets the type
derive it. `at_I_A` still means phase current, so nothing written
before this moves.

`voltage` names the level the figure is read at, defaulting to the
view's. Without it a bare current was taken in *each* referenced
element's own frame, so one number meant two different currents across
a transformer and the drawn margin contradicted the report.

A condition and a bare current are alternatives; declaring both is an
error rather than a rule about which wins.

==== Pointing at one stage

A reference means the element as a whole -- the composite, which is
what the relay trips at. Add a stage to mean just that stage:

[source,tc]
----
annotate { primary = R_850:46/energ; backup = R_SEL:46; at_I2_A = 225 A; }
----

which is what a study whose stages are alternatives under different
conditions needs: one inrush-blocked, one not, and the margin that
matters is to the one that is armed.

Where an element's stages are drawn separately
(`view { stages = "individual" }`), a margin to the element as a whole
measures the *closest* pair of stages, that being the binding gap. Where
the sheet draws the composite there is only one line per element, so the
margin is to that -- otherwise the arrow would end in mid-air.

==== Margins: in time, and in current

The vertical arrow measures a *time* margin between two curves at one
current. Its horizontal counterpart measures a *current* margin at one
time, reported as a percentage -- which is how a current-grading margin
is quoted, amps meaning little without knowing where on the axis you
are:

[source,tc]
----
annotate {                          # curve to curve
    primary = R_FDR:51;
    backup  = R_INC:51;
    at_t_s  = 1 s;
    label   = "Current margin";
}

annotate {                          # curve to a fault level
    primary = R_RMU:50;
    at_t_s  = 20 ms;
    fault   = "2ph min";
    label   = "below min 2ph";      # -> "below min 2ph +52.9%"
}

annotate {                          # curve to a marked point
    primary = R_RMU:50;
    at_t_s  = 20 ms;
    point   = "TX inrush";
    label   = "above inrush";       # -> "above inrush -16.9%"
}
----

`at_t_s` is what makes it a current margin. The far end is another
characteristic (`backup`), a declared condition (`fault` / `scenario`),
or a marked point (`point`) -- a pickup is as often quoted against a
fault level or an inrush peak as against another relay. The percentage
is of the primary's current, and both ends are put on the sheet's own
axis before they are compared, so the figure is the one the drawn arrow
spans.

A current is read as *the smallest current whose operate time is at or
below* `at_t_s`. On an inverse curve that is the point where it crosses;
on a definite-time stage, which is flat, it is the pickup -- which is
the answer meant.

==== Taking the current from a condition

Neither block needs the current typed in. Name a declared condition --
a `fault` or a `scenario` -- and the figure comes from the study, at the
quantity the sheet is drawn against, in the frame of whatever the mark
belongs to:

[source,tc]
----
point "ACB clears" {
    scenario = "system normal";      # instead of I_A
    voltage  = "HV";
    t_s      = 2.00 s;
}

annotate {
    primary   = R_850:46;
    backup    = R_FDR:46;
    scenarios = ["system normal", "one tx out"];   # one margin each
    label     = "CTI";
}
----

`fault`, `faults`, `scenario` and `scenarios` are all the same key: a
condition, one name or a bracketed list of them. Name several and the
mark is drawn once per condition, each at its own current -- which is
how a margin is shown at both a maximum and a minimum fault on one
sheet. A point drawn several times has the condition appended to its
label, so the markers can be told apart.

For a margin, each side is read in *its own* frame, exactly as grading
does, so the figure drawn is the one the report computes. A scenario
that declares both levels is not referred at all.

A point states its current *or* names a condition -- doing both is an
error rather than a precedence rule to remember. Naming a scenario that
declares nothing at the point's level is an error too: the mark asks for
a position that was never measured.

==== Which current the sheet is drawn against

By default the axis is simply *current*, and every curve is drawn
against it whatever that curve measures:

[source,tc]
----
view { voltage = "HV"; }                 # quantity = any, the default
----

That is the case where you want several characteristics on one sheet
without arguing about components. The legend states each curve's
measured quantity, which is what keeps a mixed sheet readable.

Naming a quantity opts into a stricter sheet:

[source,tc]
----
view { voltage = "HV"; quantity = I2; }  # or 3I0, I0, I1, 3I2, phase, any
----

Then only elements measuring that quantity are drawn, the rest are
counted in the legend, and each fault rule stands at the fault's value
of that component. The axis title names it, so the units are never a
guess: `Current (A primary · I2 · HV · 33 kV)`.

===== Fault types, and mixing quantities on one sheet

At a single fault the phase current and the sequence components are not
independent -- they are fixed multiples of one another, decided by what
kind of fault it is. Declare the type and the tool knows the ratios:

[source,tc]
----
faults {
    "F_2ph" { I_A = 390 A; type = two_phase; voltage = "HV"; }
}
----

Types are `three_phase`, `two_phase`, `two_phase_earth`,
`single_phase_earth`. Against the condition's *own* declared phase
current, and with `Z1 = Z2`:

[cols="1,1,1,1,1", options="header"]
|===
| Type | `I1` | `I2` | `I0` | residual `3I0`

| `three_phase` | `I_A` | 0 | 0 | 0
| `two_phase` | `I_A/√3` | `I_A/√3` | 0 | 0
| `single_phase_earth` | `I_A/3` | `I_A/3` | `I_A/3` | `I_A`
| `two_phase_earth` | -- | -- | -- | --
|===

`two_phase_earth` derives nothing: its split between the sequence
networks depends on `Z0`, which the language does not carry, so declare
its components.

A declared component always wins over a derived one -- writing
`I2_A = 225 A` is how you override the table, and it sets the display
ratio as well as the graded value.

Naming the condition a sheet depicts unlocks two things:

[source,tc]
----
view { voltage = "HV"; quantity = I2; condition = "F_2ph"; }
----

* **Curves convert onto the axis.** A phase element is drawn at
  `I_phase = √3 × I2` for a phase-phase fault, so phase and
  negative-sequence characteristics can be read together. On a log axis
  a conversion is a constant shift, so operate times are untouched --
  only the abscissa moves. Each converted curve is named in the legend
  with the multiplier that placed it -- `R:51: phase drawn on the I2
  axis, x0.577` -- because its position rests on the depicted
  condition's ratios rather than on its own setting, and the multiplier
  is what makes that checkable against the axis.
* **Elements the condition cannot operate are suppressed.** On a
  `three_phase` condition there is no `I2` and no `I0`, so earth-fault
  and negative-sequence elements are left off rather than drawn where
  they could never operate. So is an element whose current cannot reach
  the sheet's level at all -- an HV residual element behind a delta is
  off *every* sheet of an LV earth fault, not only the residual one.
  Each is named in the legend with its reason:
+
[none]
* `... 51G measures residual 3I0, which does not cross HV to LV`
* `... 51G carries no residual 3I0 at HV under LV earth fault`

`condition` takes a scenario as readily as a fault. With a scenario the
ratios come from *the level the sheet is drawn in* -- never from another
level's figures, which would mix two turns ratios into one number:

[source,tc]
----
view { voltage = "HV"; quantity = I2; condition = "LV earth fault"; }
----

===== The same component in another scaling

`3I2` is three times `I2`, and `3I0` three times `I0`, whatever the
fault is. Those need no condition: an element set in `I2` is drawn on a
`3I2` sheet at a third of its own current, and a residual element
belongs on an `I0` sheet. Only relating *different* components -- phase
to `I2`, `I2` to `3I0` -- needs a condition to supply the ratios, and
the legend says so by name when one is missing.

===== Zero sequence across a transformer

Whether zero sequence reaches another voltage level depends on the
windings: a delta blocks it, a star-star with both neutrals earthed
passes it. The tool cannot know, so the study says:

[source,tc]
----
system {
    voltages { "HV" { kV = 33; } "LV" { kV = 0.48; } }

    zero_sequence {
        "HV" to "LV" = blocked;      # delta winding
        # "HV" to "LV" = continuous; # YNyn, both neutrals earthed
    }
}
----

Undeclared, a residual figure will not be referred between levels and
the pair is reported rather than graded on a guess. Positive and
negative sequence always refer, scaling with the turns ratio.

NOTE: Fault *rules* come from the `faults` block. A `scenario` drives
grading but draws nothing yet, so a study using scenarios alone has no
rules on its plot; declare a `faults` entry for the condition you want
marked.

==== The legend follows the view

The legend describes what is on the sheet, not what the file declares.

* A fault outside the current `view` has no rule on the plot, so it has
  no legend entry either -- an entry maps a dash pattern to a name, and
  says nothing when that dash is nowhere to be seen. Zoom out and it
  comes back.
* A marked `point` that *is* on the plot is left out of the panel: its
  marker already carries its label, so an entry would repeat it.
  A point that falls outside the view is listed, because that is then
  the only place it appears.

Both rules exist to keep the panel for what needs explaining. A legend
too tall for its space sheds detail before it sheds entries.

==== Labels place themselves

You do not position labels. Each one is anchored to its point, curve or
arrow, and the renderer puts it beside that anchor -- right by
preference, then left, then above or below. When two anchors are close
enough that the labels would overprint, the later ones are moved clear,
and any label moved far enough that the connection is no longer obvious
gains a thin leader back to its anchor.

Labels never leave the plot, and placement is deterministic: the same
study always produces the same sheet, so a reissued drawing diffs
cleanly.

If a cluster still looks crowded, the fix is in the study rather than
the label: narrow the `view` so the anchors spread out, or move some of
the marked points to a second sheet.

=== view

What is on screen, not what is true:

[source,tc]
----
view {
    voltage     = "HV";            # frame every curve in the 33 kV side
    stages      = "individual";    # or "composite" (default)
    current_min = 100 A;
    current_max = 30 kA;
    time_min    = 20 ms;
    time_max    = 100 s;
    current_pad = 0.2;             # padding when bounds are automatic
}
----

Set the bounds explicitly if the automatic range is unhelpful --
auto-ranging can run wide and squash the curves.

=== view -- one per sheet

A study may declare several views. Each is one sheet: a phase sheet and
a negative-sequence sheet of the same network, or the same grading under
two conditions. Name them, and each carries its own title:

[source,tc]
----
view "Phase grading" {
    voltage   = "HV";
    quantity  = phase;
    condition = "3ph min";
    title     = "Broadsound BESS RMU — phase grading";
}

view "I2 grading" {
    voltage   = "HV";
    quantity  = I2;
    condition = "1ph min";              # the scenario
    title     = "Broadsound BESS RMU — negative-sequence grading";
    subtitle  = "480 V earth fault seen at 33 kV";
}
----

The playground shows a picker beside the plot when a study declares more
than one. Nothing changes for a study with a single unnamed `view`.

Without the playground -- the CLI, or the API -- the sheet is chosen in
one of three ways, most specific first:

[source,bash]
----
tc-curves render study.tc --svg -o out.svg --view "I2 grading"
----

[source,tc]
----
view "I2 grading" { default = true; ... }   # when nothing else says
----

and failing both, the first declared view. An unknown `--view` name is
an error listing the sheets the study does declare, rather than a
silent fall back to the first: the point of asking was to get a
particular sheet. From the API, pass the view itself:
`renderStudy(result, { view: result.study.views[1] })`.

`title` and `subtitle` on a view override `page { title }`, which every
sheet shares -- a negative-sequence sheet headed "Phase grading" because
the page said so is worse than no title. `page` keeps the paper and the
decoration; the view keeps what the sheet is *of*.

[NOTE]
====
Presentation stays in the presentation layer. A `scenario` is only what
the fault study measured, and stays readable as such; the *view* names
the condition it depicts. Putting a `view` inside a `scenario` would
have mixed the two and needed a precedence rule between the sheet's own
settings and the top-level ones -- and it could not express two sheets
of one condition, which is the common case.
====

=== page

Paper, decoration, and where the legend goes:

[source,tc]
----
page {
    size        = "A4";            # A0..A5, Letter, Legal, Tabloid
    orientation = "portrait";      # or landscape (default)
    margins_mm  = 4;               # all four sides; 0 = edge to edge
    stretch     = true;            # give the plot the unused band below the axis
    theme       = "light";
    border      = true;            # drawing frame + title block
    legend      = { style = "direct"; };
    axes        = { mirror = true; };       # repeat the scales top and right
    faults      = { width_px = 1.5; };
    title       = { text = "Northgate 11 kV"; subtitle = "Feeder grading"; };
}
----

==== Fitting a portrait sheet

Three levers, in the order they matter:

. `legend { style = ... }` -- a right-hand column costs about a third
  of a portrait sheet's width. `inside` floats the same panel over the
  plot; `direct` drops it and labels each curve in place; `none`
  removes identification entirely.
. `stretch = true` -- reclaims the fixed band reserved below the axis
  for stacked fault names.
. `margins_mm` -- `4` is a sensible print margin, `0` fills the sheet.

A legend too tall for its space sheds detail rather than running off
the page: make and model first, then settings, then names only, and
finally `+N more not shown`.

==== Notes, and getting the space back

The panel ends with a `Notes` block: what the sheet left out and why --
a curve the condition suppresses, a marker whose component this axis is
not drawn in, a scenario with nothing to say at this level. It sits at
the foot because the list of characteristics is what a reader wants
first; the caveats are what they come back for.

It takes its space from the panel, pushing the conditions up rather
than running off the page. On a crowded sheet it is dropped along with
the other detail as the legend tightens, and it can be turned off
outright:

[source,tc]
----
page { legend = { notes = false; }; }
----

If the panel is still short of room, in the order that costs least:

. `legend { style = "inside" }` floats it over the plot, or
  `style = "direct"` drops it and labels each curve in place -- either
  returns about a third of the sheet's width.
. `page { stretch = true; }` reclaims the band reserved below the axis.
. `margins_mm = 4`, or `0` to fill the sheet.
. Split the study across two `view` blocks; each sheet then carries
  only the curves and notes that belong to it, which is usually the
  real fix when one panel is trying to explain two stories.

==== Settings in secondary amps

A study is written in primary amps because that is what the fault study
gives, but the number an engineer types into the relay is the secondary
one. `legend { currents }` asks for that figure, whatever the abscissa
is doing:

[source,tc]
----
page {
    legend = { currents = "secondary"; };   # or "both", or "primary"
}
----

* `primary` -- as declared. The default.
* `secondary` -- divided by the relay's `ct_ratio`: a 720 A pickup
  behind a 600/5 CT reads `6 A sec`.
* `both` -- `720 A (6 A sec)`.

Independent of `view { axis }`, which decides what the *current axis*
is: a sheet can have a primary-amp axis and settings-sheet figures
beside it, which is what a commissioning copy wants.

The conversion needs `ct_ratio` on the relay. An element without one
keeps its primary figure and is named in the legend -- a panel headed
one way and figured the other is out by the ratio, which is the sort of
error that reaches a relay.

== Reading the output

A margin report row per grading pair:

----
grade R_FDR:51 / R_INC:51:
    fault           = F_lv_max (I_f = 6400 A on LV)
    CTI_min         = 0.300 s
    seen by primary = 6400 A    seen by backup = 2133 A
    t_primary       = 0.274 s        (M = 13.33)
    t_backup        = 1.912 s        (M = 2.96)
    achieved margin = 1.639 s        -- pass
    overall         : PASS (worst 1.639 s at 6400 A)
----

`seen by backup` differs from `seen by primary` when a transformer sits
between them: ampere-turns balance, so the 33 kV winding carries
`6400 x 11/33 = 2133 A`. Each multiple is computed from the current in
that relay's own winding.

== Diagnostics you are most likely to meet

[cols="1,1,3", options="header"]
|===
| Code | Severity | Meaning

| `MEASURES_REQUIRED` | error | A `neg_seq` element does not say whether its pickup is `I2` or `3I2`.
| `SEQUENCE_DATA_MISSING` | error | An element measures a component the fault or scenario does not declare.
| `SEQUENCE_ACROSS_LEVELS` | error | A zero-sequence figure would have to cross a transformer. Declare it at the relay's own level.
| `CT_RATIO_MISSING` | error | A secondary-side pickup with no `ct_ratio` to convert it.
| `DUPLICATE_KEY` | error | A key assigned twice in one block.
| `MISSING_VALUE` | error | An `=` with no value after it.
| `MARGIN_BELOW_CTI` | error | A declared `margin_s` is below the `CTI_min_s` floor.
| `ZERO_DELAY_NOT_PLOTTABLE` | warning | `t_delay = 0 s`; the stage cannot be drawn on a log axis.
| `GRADE_MIXED_QUANTITY` | warning | The two sides of a grade measure different currents. Legitimate, but stated.
| `RELAY_VOLTAGE_UNSPECIFIED` | warning | A relay has no `voltage` in a study with several levels.
| `FAULT_SINGLE_POINT` | info | Only `I_A` given, so `min_A` and `max_A` default to it.
|===

== Writing a study from scratch

A checklist, in the order that avoids rework:

. **Levels first.** `system { voltages { ... } }`. Every relay and
  fault refers to a level by name.
. **Fault data next**, from the network study. Use `faults` for phase
  currents; use `scenario` if any element measures a sequence
  component, and declare each level explicitly.
. **One relay per protected item**, with `ct_ratio` if any pickup is in
  secondary amps.
. **Elements in device-number order**, each with `function`. Add
  `measures` to every `neg_seq` element. Give instantaneous stages a
  real operate time, not zero.
. **Grade downstream against upstream**: `primary` is the element that
  must clear first. Add `upstream = true` unless you have a reason not
  to.
. **`view` and `page` last** -- they change presentation only. Bound
  the current axis explicitly.
. Run `check`, then `report`, then render and *look at the plot*.
  Curves that vanish, labels that collide, and margins in the wrong
  direction are all obvious in the picture and invisible in the source.

=== Common mistakes

* Omitting units. `I_pu = 480` is an error; write `480 A`.
* Using `t_delay = 0 s` for an instantaneous element. It will not
  appear on the plot.
* Grading with `primary` and `backup` the wrong way round. The primary
  is downstream and must be *faster*. A negative margin usually means
  they are swapped.
* Referring a residual current across a transformer. Declare it at each
  level with a `scenario`.
* Assuming the study's largest fault is visible to a sub-feeder deep in
  a cascade. Bound the upstream sweep with `upstream_to`.
* Expecting the tool to compute fault levels. It does not; they are
  input.
